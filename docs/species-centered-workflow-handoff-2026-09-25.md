日期：2026-09-25。状态：已实施；下文保留交接时的目标与验收清单，实际验证范围见第 9 节和本次交付报告。
这份交接承接用户对产品定位与研究起点的确认，供新对话实施；现有实现、历史验收和本轮目标须分别核对。

## 1. 已确认的产品方向

> ReacNet Scope 是面向反应分子动力学（MD）的证据分析工作台。它围绕研究者关注的物种，将 ReacNetGenerator（RNG）记录组织为可探索的候选反应路线，并将路线中的每一步关联到可核查的具体事件，帮助研究者形成、筛选机理假设，并评估其在现有 MD 数据中的证据支持。

用户通常先确定关注的物种，再研究其生成、转化路线和变化趋势。由此确定：

- 物种是持续的研究对象，候选路线是核心分析对象。
- 反应检索提供直接生成/消耗通道及步骤记录，服务于路线研究，也保留独立查询用途。
- 具体事件是一次反应发生的记录；证据核查是围绕所选事件查看参与者、键变化、结构与轨迹的动作。
- 不以“验证机理”描述软件已经完成的判断。逐步事件支持、整条路线的连续观测支持和机理成立具有不同含义。

## 2. 为什么还需要这一轮改造

现有[目标物种开发计划](target-species-workflow-development-plan.md)记录了“路线 → 步骤 → 实例 → 结构/导出”的实现和历史测试结果。
本轮复用并核验该链路，将其纳入持续的物种研究上下文。旧文档的“已实施”不代表本轮目标已经完成。

本次静态核对发现：

1. `navigation.py` 仍以物种发现、反应路径、证据核查、物种趋势组织四个分析工作区；反应任务中的默认检索仍显示为“反应路径”。用户需要自行把这些工具串起来。
2. `callbacks.py` 的 `_show_species_detail` 和 `_focus_reaction_structure_species` 都修改 `app-store.selected_smiles`。物种列表选择、局部反应浏览焦点和后续分析入口复用这一字段，不能直接将它认定为稳定的研究物种。
3. `candidate_workbench.py` 已有起点、终点、研究物种交接、逐步探索、事件分页和返回状态，应逐项复用。
4. 旧[使用流程提案](target-species-workflow-proposal.md)仍包含“寻找生成路线必须另选起点”的历史文字；有效 [ADR-0026](adr/0026-search-candidates-by-anchor-mode.md)已允许仅终点的逐步前驱探索。实施不能恢复这个旧限制。

工作区已有多处未提交修改，涉及导航、候选图、数据管理、样式、测试和文档。新对话先重新检查 `git status` 和相关差异，保留这些修改；不要把历史测试数字当成本轮验证。

## 3. 目标交互

主流程：**选择 RNG 数据 → 找到并确认精确物种 → 进入物种研究 → 探索路线 → 选择步骤及具体事件 → 核查结构/轨迹或导出 → 返回原研究位置**。

“研究概览”提供当前 RNG 数据及研究物种摘要，但不是选定物种后的必经入口；用户可先打开任一适用工具。物种研究内部提供以下视图，主要操作突出路线探索：

| 视图 | 用户要回答的问题 | 使用现有能力的方式 |
| --- | --- | --- |
| 研究概览 | 我在研究谁，下一步要看什么？ | 精确结构、已有统计及可用趋势摘要；突出“查生成路线”“看后续转化” |
| 路线探索 | 哪些候选路线通向它，或从它继续转化？ | 终点逐步前驱探索、起点逐步探索、指定另一端的双端搜索 |
| 相关反应 | 哪些反应直接生成或消耗它？ | 直接生成/消耗通道；包含未满足候选主线载体条件的反应 |
| 丰度趋势 | 它在已有记录中如何变化？ | 复用单来源丰度查询；多来源比较保持独立来源选择 |

路线探索的三种动作准确带入锚点：

- **查生成路线**：研究物种作为终点，逐步查看已观测正向转移的前驱；不要求先知道起点。
- **看后续转化**：研究物种作为起点，沿选中分支逐步探索。
- **连接指定物种**：保留研究物种并明确其作为起点或终点，由用户选择另一端，再执行双端搜索。

单端探索每次扩展一步，不展示成已穷尽全部生成历史。切换视图保留有效结果与浏览链，不因为导航自动重跑候选搜索。

点击反应步骤就在图旁打开详情，依次浏览完整反应、支持事件和当前事件的键结构。较复杂的结构、局部轨迹和导出可以展开大视图，但始终带着所选事件和返回位置。
窄屏详情可转为下方或全宽，避免压缩结构图。此布局为实施建议，具体组件尺寸由实际浏览器验收决定。

“具体事件”和“证据核查”组成一条选择与检查链路，用户无需从两个空白入口分别重新选择。同一详情组件也承接直接反应和独立事件检索。

导航承载关系调整为：RNG 数据负责来源管理，物种发现负责精确物种检索，物种研究承载上述视图及元素分布。全网反应式/事件检索和多来源比较保留独立工具入口；元素分布也可直接打开，不强制先选择研究物种。
反应式检索明确称为“反应检索”或“按反应式检索”；候选路线保持清楚的独立任务含义。

## 4. 先固定状态归属

沿用现有 Current Dataset 与两阶段切换。先盘点 stores 和回调写入点，再以最少必要修改表达下列状态；不预设引入新的状态框架。

| 状态 | 何时变化 |
| --- | --- |
| 研究物种及其数据/修订归属 | 在物种发现结果中选中精确结构，或从局部焦点显式改为研究另一物种 |
| 当前查看的中间物种、反应步骤、具体事件 | 浏览图或选择详情；本身不替换研究物种 |
| 已提交查询、已选路线/探索分支、分页及返回位置 | 显式查询、展开、切换结果或返回 |
| 轨迹、几何预览及导出资格 | 绑定所选事件与来源修订；事件或相关参数变化即失效 |

关键规则：

- 查看中间物种 B 时，研究对象 A 保持不变；显式改为研究 B 后，才更新依赖研究对象的视图。
- 关闭物种检索详情或表格刷新产生空选择，不能意外清空已建立的研究对象。
- 切换 RNG 数据成功后清理旧来源的选择和结果；失败保留原研究。源修订变化使旧证据引用失效。
- 同一数据内也要核对查询、步骤及事件身份；旧请求的迟到结果不能覆盖新选择。
- 从事件核查返回，恢复原查询、路线/分支、步骤、事件页和视图，不自动重新搜索。
- 趋势时间窗只有在对应服务支持时才能用于路线过滤；不能将“当前看到的时间范围”暗中当作候选查询范围。

## 6. 科学含义与能力反馈

- 研究物种使用 RNG 精确结构身份，分子式只辅助检索。已知代表结构限制在相关位置提示，具体事件使用其真实键状态。
- 各步骤可以来自独立事件。连续历史检查仍为可选操作，未检查不等于无支持，未找到连续链不否定候选资格。
- 反应总发生数、候选步骤支持数、当前页数目分别表达；查询截断不包装成查全，计数不包装成机理重要性。
- 无坐标时仍可查看已有事件和键证据；坐标、连续历史、几何导出分别按能力反馈，不用统一“不可用”遮蔽已有结果。
- 页面查询消费已发布索引和有界数据；已有 preparation、来源只读、单位与 DFT 初始几何要求继续生效。

论文调研中的方法假设和扩展计算建议不自动成为本轮开发范围。本轮首先交付可用的物种研究流程。

## 7. 验收清单

1. 从分子式命中的多个结构中选定 A，进入概览；所有后续交接使用所选精确身份。
2. 仅以 A 为目标查看候选前驱，继续展开并返回；无需先补一个起点。
3. 从 A 探索后续转化或与指定另一端搜索，保留方向、范围与截断说明。
4. 研究 A 时查看中间物种 B、共同反应物、步骤和趋势，研究对象仍为 A；显式重设才改为 B。
5. 从步骤选择非首个事件，跨事件页切换，查看结构/轨迹/导出后返回，事件身份和浏览位置一致。
6. 快速切换事件、查询、物种、RNG 数据或源修订，旧结果、轨迹和下载资格不会混入当前上下文。
7. 分别演示有效空结果、缺索引、缺坐标、查询截断、加载失败；连续历史未检查或未找到不阻断逐步核查。
8. 直接检索反应/事件仍可独立使用；比较来源选择不改变普通分析使用的 Current Dataset。
9. 浏览器验证长反应式、多事件、侧边/展开详情、窄屏、返回及旧会话迁移；没有浏览器验证就明确保留缺口。

按[测试指南](agents/testing.md)选择现有回归，重点为 Dash smoke、workbench、dataset switch、候选图与事件工作台、证据导出和浏览器测试。
先做阶段定向验证，跨模块修改完成后运行 `uv run --locked pytest -q`，浏览器另按指南运行。
真实案例记录输入来源、修订、查询和事件身份；历史报告和小 fixture 不能替代本轮真实规模、视觉或跨平台验收。

## 9. 本轮实施记录

- 阶段 0：核对了未提交改动并保留原有工作；沿用候选路线、步骤事件分页、结构/轨迹检查与导出服务。以 `tests/test_indexed_candidate_workbench.py` 的七行事件样例固定多路线、多事件回归：`CCO → CC(=O)O`、最多三步，返回经 `CC=O` 与 `COC` 的两条候选；前一路线首步有两条事件。该样例不含分子关联或坐标。
- 阶段 1：新增绑定 Current Dataset 与源修订的精确研究 Species；物种发现中选中精确结构即开始研究，候选图中的其他 Species 仍需显式设为研究对象。反应参与者及中间 Species 保持局部焦点。研究身份跨工具持续保留，更换研究对象时清理依赖结果。
- 阶段 2：概览直达仅终点前驱、仅起点后续和明确方向的双端搜索；复用原有分支返回、图选择、事件分页及证据交接。步骤详情与路线图在桌面并排，窄屏纵排。
- 阶段 3：相关反应、单来源丰度、独立反应/事件检索及多来源对比保留各自入口；研究物种和局部通道焦点分别保存。旧会话页面经现有重定向迁移。
- 阶段 4：新增研究身份、修订失效与快捷入口回归，并用 Chromium 检查桌面/紧凑布局的研究流程及相关既有功能。最终测试数字与未覆盖环境见本次交付报告。

后续交互修正：精确结构列表的选中即建立研究身份，物种详情允许先进入任一适用工具；研究概览是可选入口。局部反应参与者仍须显式设为新研究物种，避免浏览时意外替换原研究对象。
