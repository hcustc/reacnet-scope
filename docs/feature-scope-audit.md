# 功能范围审查：聚焦已有轨迹的解释与复核

日期：2026-09-19。状态：建议，未采纳为新产品契约；本轮没有删除功能。

## 范围与判断依据

检查当前工作树中的 Dash 入口、服务门面、候选路径/事件路径/谱系/命运/速率/QC 核心实现、已有测试入口，以及仓库内目标生成和模型迭代分析报告。不是逐行代码审计，也没有重新核验报告引用的全部原始轨迹或运行大型性能实验。此前本任务全量测试为 543 项通过；这不能替代真实科学任务、浏览器和规模验收。

当前优先任务从实际报告归纳为：目标物种是否出现；何时、多少；如何生成和消耗；选定原子来自哪里、去了哪里；具体事件能否回到轨迹复核；不同温度或模型迭代的证据是否可比。该归纳不是对未来全部研究需求的断言。

事实来源：

- [产品设计基准](software-design-baseline.md)与[领域词汇](../CONTEXT.md)。
- 本地 `analysis_outputs/target_generation_20260918/report.md`：目标 Species 的真实生成分析。
- 本地 `analysis_outputs/chlorocyclopentadienone_20260918/iteration_comparison/report.md`：iter25/iter32 比较。
- 本地 `analysis_outputs/chlorocyclopentadienone_20260918/miso_assessment.md`：miso 身份审计。

## 总体结论

保留“数据集 → 精确物种 → 直接通道 → 事件 → 局部轨迹/原子谱系 → 可复核导出”主线。
停止把每个分析概念都扩成独立工具。削减没有明确决策用途的评分、提前承诺的能力和重复操作入口；不能因为上层功能暂缓就删除共用的事件/分子连续性索引。

“不建议继续投入”不等于算法错误，也不等于必须立即删除所有已有代码。已实现且维护成本低的可选导出，和需要持续投入的研究平台，应区别对待。

## 功能处置矩阵

| 功能 | 当前证据与完整度 | 建议 |
| --- | --- | --- |
| 数据集选择、能力检查、索引准备、任务取消/续建 | 核心服务与会话链路已有实现，是大型轨迹查询前提 | 必须保留；界面简化但不能砍数据一致性与来源检查 |
| 精确物种/分子式检索、结构查看、质量检索 | 主线可用；真实报告暴露代表标签与原始键结构的差异 | 优先完善身份解释；质量查询保留为辅助入口，不扩展成质谱处理平台 |
| 生成/消耗通道、反应式检索 | 已直接用于目标生成分析 | 必须保留；独立反应式检索降为另一查询入口，复用结果与详情 |
| 事件搜索、时间分布、局部轨迹、键变化及事件包 | 是复核真实反应的依据 | 必须保留；补好从统计到事件、从事件到帧的点击交接 |
| 单/多物种时间演化 | 已用于消耗曲线与目标检出 | 必须保留；多来源绘图应与比较页面复用来源选择和身份确认 |
| 分子谱系与有界回穿记录 | 真实报告用分段谱系追到了 2CP，并记录分裂/重并 | 提高优先级；优先继续追踪分支、书签、分支摘要和可见停止原因 |
| 元素分布演化 | 已有独立实现，提供总体组成视角 | 保留为可选统计视图；无具体问题时不再扩建专门分析体系 |
| 多条件/模型对比 | 有反应统计及逐来源精确物种比较；真实报告确实需要 | 保留并收敛；优先明确模型、温度、RNG 参数、身份口径和独立重复 |
| 候选路径发现 | 已有网络级有界展开和逐步事件摘要；不是旧文档描述的纯 occurrence 路径原型 | 只保留受问题约束的路线探索与各步证据；暂停继续扩大候选平台 |
| 候选综合评分、能量 CSV 评分 | 已有频次/相似性等加权分数；能量结构只有 score、能量/能垒、单位与来源等少量字段 | 优先移除普通产品中的评分与能量打分入口；独立指标可以保留用于排序 |

| Continuous MD Support | 已接受独立验证契约；当前候选 UI 两个时间约束控件禁用，服务记录 deferred | 不展示未完成操作；只在选定路线的真实需求下逐步实现有界验证，不补一整套通用平台 |
| 通用 Species Fate | 已有核心、UI、导出；结果明确标记初始左删失检测不完整 | 冻结独立产品扩张；保存核心与脚本能力，等明确终点统计课题再启动 |

## 最应优先停止的投入

### 1. 候选路径的综合“好坏”评分与能量 CSV 排名

[实现](../reacnet_scope/candidate_paths.py)包含固定权重和频次、结构相似性等归一化分量。当前网络模式已排除时间/连续性分量，不能指责它仍默认把这两者当作候选成立条件；但剩余综合分数也没有给出“本课题主生成路线”的验证依据。

更关键的是，实际迭代比较报告已经展示：三步网络连接和一个具体目标实例的长分支谱系不是同一件事。频繁的开闭环也不能自动解释成独立生成次数。

建议：删除面向普通使用者的综合分数、最佳路线暗示及能量 score 导入。保留步数、每步事件计数、来源和未验证状态等独立事实。真正需要目标路线时，再收敛目标和载体约束。不要把此建议误解成取消所有网络可达性查询。

### 2. 默认展示并继续扩张表观 k

[速率模块](../reacnet_scope/kinetics.py)不是空壳：它确实实现了指定一/二阶质量作用模型下的事件数/反应物暴露估计，并有统计区间。问题是产品优先级与解释条件，而不是“公式尚未写好”。

目标生成报告中的 269 条生成记录、269 条消耗记录以及反复开闭环，说明日常任务首先需要区分事件、原子集合、往返和积累。为看通道就要求处理时间/盒体积/单位，会把工具重心带离这个问题。

建议：保留物理时间换算、窗口、事件计数和丰度；将 k 留在明确研究用途的可选分析。没有专门的验证课题时，不继续做自动动力学模型或“主机理”推断。撤掉速率入口不能顺带删掉轨迹 PBC 所需的盒信息。

### 3. 通用命运分析产品化

[Species Fate](../reacnet_scope/species_fate.py)已经有完整命运、部分命运、吸收终点、分支及删失处理，不应称作毫无实现。但 `_build_result_document` 仍返回 `left_censored_detection_complete=False`。UI 还要求用户输入终点、锚点及元素映射等，当前回调没有补齐从普通物种/谱系交接到全部证据下钻的流程。

“这个产物怎么来的”更适合事件与分子谱系；“所有形成 episode 的锚点后代最终落入哪些预定义终点”才是 Fate 的问题。二者不能互相替代。

建议：独立页面降为实验/脚本能力，不继续堆统计面板。保留现有算法和共用 continuity substrate，直到有明确、重复使用的终点统计问题与验收样例。

### 4. 独立手写路径验证和提前摆出的连续支持设置

[事件路径实现](../reacnet_scope/event_paths.py)的 `_load_event_nodes` 无 WHERE 限制遍历 events；`_analyze_event_paths` 随后建边，再处理指定序列。这是规模边界问题，不能由小 fixture 测试通过推出生产适用。

[候选服务](../reacnet_scope/analysis_services.py)现在走网络展开与索引摘要，和上述实现必须分开看。其时间约束会被记录为 `continuous_support_filters_deferred`；[候选页面](../scripts/webapp_dash/app.py)对应控件禁用。正式 Carrier Chain 支持验证不能仅靠换名宣布完成。

建议：收起未完成控件；保留高级核查能力，优先支持从现有选择生成输入、受限索引查询。不要投入大型手写序列工作台，也不要为了实现所有 ADR 目标一次性补完整候选平台。

### 5. 完整 QC/动力学平台

[QC 预检](../reacnet_scope/reaction_readiness.py)给出实际交接检查；`kinetics_applicability` 当前固定为 `insufficient_evidence`，persistence 也明确未评估。这些限制是诚实报告，不是删除所有检查的理由。

应保留初始几何导出所需的事件身份、原子映射、单位、PBC 与几何检查。停止线是导出可复核的初始几何和元数据。没有具体课题驱动时，不开发调度器、量化结果解释平台、TS/IRC 自动化和理论速率求解。

## 不能误砍的三项

1. **分子谱系。** 实际目标分析有 17/16/30 次分段查询，有一支因 chunk limit 未追完。它的缺口是继续追踪分支和摘要，不是缺少科学用途。碳片段分裂/重并也说明不能用短线性路径替代它。
2. **跨来源比较。** iter25/iter32 的真实差异需要可比证据。应合并重复的多文件输入和绘图入口，但不能删除逐来源目标映射、重复定义和来源审计。
3. **来源/身份审计。** miso 报告证明代表名称可能遮蔽原始键级结构。应明确展示 RNG 标签与原始 Molecular Evidence 的关系，不修改源标签来伪装已恢复身份。身份确认比新增评分更有价值。

## 推荐的信息架构和开发顺序

建议普通导航最终收为五类：数据集；物种与趋势；反应与事件；轨迹与谱系；对比。元素分布、直接反应式查询、路线探索保留为相关工作区内的工具。Fate、k、QC 扩展不再占默认主线。

实施顺序：

1. 先冻结候选评分/能量导入、通用 Fate、动力学和 QC 平台的新增需求。
2. 隐藏未完成入口、合并重复 UI，保留兼容 API 与已有导出，减少一次性迁移风险。
3. 优先做精确身份审计、分段继续追踪、事件书签与轨迹交接、可比数据集清单。
4. 用真实目标案例验收：目标检出与 miso 解释；四组碳锚点的生成记录；分裂重并谱系；iter25/iter32 的证据层级比较。明确预算与未完成分支，不要求产出“唯一主机理”。
5. 若决定删除正式能力，再同步 CONTEXT、设计基准、有效 ADR、CLI/API 和测试；本报告不自动废止已有契约。

目前 Dash 布局约 4.4k 行、回调约 10.9k 行、CSS 约 7.4k 行。它们说明更应先收敛功能入口和状态责任，不构成某个科学功能应该删除的独立证据。此前 UI 重排改善了可见性，但不能证明每个被整理的功能都值得继续投入。
