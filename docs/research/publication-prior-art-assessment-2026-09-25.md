# ReacNet Scope：近邻先例与论文贡献初评

日期：2026-09-25。性质：用于定位与投稿讨论的有界调研，不是完整优先权检索、投稿保证或新的产品契约。只新增本笔记；未修改软件、重处理 RNG、开展 MD/QC 或运行竞品。

## 判断

**存在高度重叠的基础功能，也存在值得形成论文的研究问题；目前不能把“物种中心 + 路径图 + 原子追踪 + 导出”当作已经成立的创新性。** 更有希望的主张是：在保留上游 RNG 证据的前提下，明确区分网络候选、逐步原子传递和具体连续历史，并以可复核结果揭示聚合路线何时被误读为真实生成历史。这是待验证的贡献假设，尚非“其他软件都没有”的结论。

论文应回答两种不同问题：软件是否解决了真实且反复出现的研究困难；所提出方法相对最接近的已有方法究竟增加了什么。前者可由工作流、性能和复现结果支持；后者需要对照与消融。界面重组有产品价值，但单独不足以证明化学信息学方法创新。

## 最接近的已确认重叠

| 工具或论文 | 一手来源确认的重叠 | 对 Scope 定位的影响与未确认项 |
| --- | --- | --- |
| ReacNetGenerator | 原论文已有交互网页、围绕给定物种查看局部网络与物种数量时间变化；当前 CLI 已有原子/键的 molecule timeline 和逐时 reaction event 输出。[原论文](https://pubs.rsc.org/en/content/articlehtml/2020/cp/c9cp05091d)、[作者预印本](https://www.cambridge.org/engage/api-gateway/coe/assets/orp/resource/item/60c7444cbb8c1aa0853da49f/original/reac-net-generator-an-automatic-reaction-network-generator-for-reactive-molecular-dynamic-simulations.pdf)、[官方 CLI](https://deepmodeling.github.io/reacnetgenerator/guide/cli.html) | 最重要的直接基线。Scope 必须明确哪些数据和识别能力属于 RNG，新增的是哪些查询、关联与核查；不能将上游导出的原子身份称为 Scope 发明。 |
| ChemTraYzer2 | 官方输出将事件表与唯一反应汇总分开；事件含起止帧及两侧原子索引，同时提供种群、速率、XYZ 和事件可视化。[官方文档](https://www.scm.com/doc/Workflows/ChemTraYzer2/ChemTraYzer2.html)、[GUI 教程](https://www.scm.com/doc/Tutorials/MolecularDynamicsAndMonteCarlo/ChemTrayzer2.html) | “反应类型 → 事件 → 原子/几何”本身已有明显先例。本次未确认其是否提供与 Scope 相同的跨步锚点连续检查及不确定结果语义；未确认不等于不存在。 |
| ReaxANA，JCIM 2025 | 论文以图操作消除组合/分离、异构化和收缩相关的振荡模式；作者源码 `compare2Step` 用前后碎片原子集合交集建立反应链接，并记录步骤。[论文](https://doi.org/10.1021/acs.jcim.5c00521)、[作者源码](https://github.com/XinChenQC/ReaxANA/blob/main/tool.py) | 原子重叠建立连接、时间化反应图、往返处理都不能泛称独创。需要比较保留原始证据的注释/折叠语义、参数敏感性和误差，而不是比较功能名称。主文全文与全部补充材料未完整取得，尚未审计其全路径连续性规则。 |
| Kobulnicky、Boafo、Barnes，ACS Omega 2025 | §2.2 从每条轨迹的状态序列建立 ensemble reaction graph，再从目标产物反向 BFS，以入向通量筛选相关路线；明确区分数据中未观测逆向与化学不可逆。[论文](https://doi.org/10.1021/acsomega.5c04493)、[开放全文入口](https://pmc.ncbi.nlm.nih.gov/articles/PMC12508971/) | 这是容易漏掉的近邻方法。时间序列与聚合网络两层、目标导向路线探索已有先例。已读方法说明未建立与 Scope 完全同义的“对任意候选另做具体载体链/锚点连续核查”契约，不能据此断言作者不能查询原轨迹。 |
| ReaxTools | 本次 GitHub 主页面 README 为 2.1，声明保留原始事件、逐事件原子重叠对及聚合 transfer 表，并提供一致性审计与反应快照；过滤图是展示产物。[官方仓库](https://github.com/tgraphite/reax_tools) | “原子来源可审计”已存在直接软件重叠。本次未固定提交或运行审计；搜索缓存中的旧 README 还宣称分子生命周期和连续路径，不能将两个版本描述拼成已验证的当前能力。正式论文比较前必须固定版本、读源码并实际运行。 |

这些先例覆盖不同层次，不能用一个“功能勾选数量”决定孰优孰劣。RNG 是 Scope 的上游；ChemTraYzer2、ReaxANA、ReaxTools 多含自身检测；ACS Omega 工作处理直接动力学轨迹集合。检测输入、采样尺度、图节点语义不同会影响公平比较。

## 其他必须承认的先例与边界

- **物种中心不是独有交互。** SCINE Heron 官方直接列出以单个 Compound 为中心导航、Pathfinder 路径搜索、Compound 结构和 Reaction 基元步骤展开。[官方功能](https://scine.ethz.ch/download/heron)。它主要围绕量化网络，不能直接替代 RNG 轨迹事件后处理，但足以反证“物种中心界面首创”。
- **详细事件可视化也不是新方向。** VARxMD 2014 已描述原子、键、碎片、物种和反应之间的分析及相邻采样帧反应可视化。[原论文](https://www.sciencedirect.com/science/article/pii/S1093326314001107)。RMD_Digging 官方仓库亦明确有轨迹产物导出及反应路径/通道分析工具；本次仅核查 README，未运行 MATLAB 或全面审计手册。[官方仓库](https://github.com/dadaoqiuzhi/RMD_Digging)。
- **减少瞬态假反应已有专门方法。** ChemXDyn 2026 用随时间变化的原子间距、价态和配位约束判别反应，并比较多个氧化体系。[原论文](https://doi.org/10.1021/acs.jctc.6c00242)。这属于检测层；Scope 当前契约不运行第二套反应检测，因此不应声称其证据展示自动提高了上游识别正确率。
- **MD 筛选后量化验证已有先例。** Schmalz 等 2024 从目标回溯 RMD 网络，再进行 NEB/驻点精修。[原论文](https://doi.org/10.1002/kin.21719)、[本仓库全文阅读笔记](schmalz-2024-path-validation.md)。仅接入 ARC、导出 DFT 或把 MD 与 QC 串联不能自动构成新方法。

## 值得论证的贡献假设

以[领域词汇](../../CONTEXT.md)、[产品基准](../software-design-baseline.md)及有效 [ADR-0013](../adr/0013-separate-candidate-discovery-from-continuous-md-support.md)、[ADR-0019](../adr/0019-separate-anchor-continuity-and-atom-provenance.md)、[ADR-0026](../adr/0026-search-candidates-by-anchor-mode.md)为准，以下是研究方向，不是新增范围承诺：

1. **逐步成立与整条历史成立分别计算。** 同一个中间 Species 可来自不同原子、不同实例。候选允许独立步骤组合；选中的具体历史检查不得越过先前消耗、连续性缺口或证据屏障。研究价值在于减少错误的历史解释，而不是把没有连续链的网络候选一律叫假反应。
2. **把可解释的原子来源事实与判断条件分开。** 保留完整反应计量、split/merge、锚点流失与外来原子进入；原子离开后返回不能恢复先前已中断的连续保留。需用重排、裂解、交换、返回等案例证明此区分会改变研究结论。
3. **保持证据和分析结果可追溯。** 原始/折叠视图、代表 Species/当次真实键状态、查询范围、源修订、预算与缺失证据分别记录。单个字段的新命名不是创新，能否让别人复核、重现并避免误判才是可衡量贡献。
4. **有界查询支撑实际规模。** 离线准备和索引后按需下钻可成为软件工程贡献，但需要与扫描/全图构建等合理基线比较，给出冷/热查询、准备开销、内存、索引大小及规模趋势；不能只报一个小 fixture 的响应时间。

当前代码的候选历史结果明确区分 `chain_found`、`inconclusive`、`not_observed_within_evidence`，见 [`candidate_evidence.py`](../../reacnet_scope/candidate_evidence.py)。设计基准不是实现完成声明；本次静态核对不替代服务、浏览器或大数据验收。曾经的“只搜起点”或“按最短优先展示”等历史描述也不能当成当前事实，ADR-0026 已修改对应规则。

## 本地已有案例能说明什么

[2026-09-21 氯酚案例](candidate-path-case-study-2026-09-21.md)记录：扩展查询得到的七个首步事件全部在下一 Transition 同原子返回；原截图第二步 77 次闭环全部具有同原子反向前序，且其原子组与原截图首步产物不相交。因此，各步都有记录不等于所展示的首步、第二步构成连续生成链。这是很好的论文动机与反例。

但它是特定数据和当时版本的案例，不能证明改进已普遍有效，也不能证明其他工具无法发现问题。需要固定后续版本、可分享的小型证据样例和真实体系复现；不能将本地未分发完整结果当作读者能访问的补充数据。本次没有重复运行这份审计。

## 最小可讨论的验证设计

| 待验证主张 | 建议对照 | 需要报告的结果 |
| --- | --- | --- |
| 避免把聚合路线误当具体历史 | 相同 RNG 输出上的物种连接图；增加逐步原子重叠；再增加连续段与首次消耗检查 | 专家/人工审计标注上的错误历史断言、可判定覆盖率、漏检、明确不确定比例；不能把不确定都计为正确 |
| 区分真实生成和反复返回 | 原始视图、固定寿命阈值、ReaxANA 式往返处理；保留可分享相同输入 | 不同窗口下结果稳定性、真实短寿命中间体的保留、返回重复计数变化 |
| 比已有软件多提供可复核信息 | 固定版本 RNG 报告 + 脚本、ChemTraYzer2、ReaxTools；ACS Omega 方法按适用输入复现 | 统一研究任务是否可完成、来源字段是否可回溯、人工操作与错误；记录不适用而非一律记缺失 |
| 实际研究收益 | 多个具有不同反应特征的体系/重复来源 | 至少一项解释因核查而改变的具体结论，并展示正例、反例和证据不足例 |
| 可交付的软件贡献 | 固定版本发布、文档、安装、数据与脚本 | 他人可复现的完整示例，明确软件和依赖版本、许可、输入来源与处理参数 |

优先做严格的相同输入消融，再做跨工具端到端比较。否则不同检测器产生不同事件，无法把改进归因于 Scope 的路线/证据方法。对于直接动力学集合与大体相反应 MD 的比较，需说明节点、轨迹集合和统计单位的适用范围。

## 论文类型与准备程度

可讨论两条路线，但都不能预先保证录用：

- **研究软件/应用论文。** 可以围绕明确研究需求、已有工具不足、完整工作流、可复现案例、工程质量及可用性进步。JCIM 的 Application Notes 接受具有科学、技术或可用性进步的新软件，但仍需说明区别和公开可用性；不能只展示新界面。[JCIM 投稿指南](https://researcher-resources.acs.org/publish/author_guidelines?coden=jcisd8)。
- **方法论文。** 需要把上面的证据层次与连续性判断写成清楚的问题、算法和实验，证明相对基线的改进及适用边界。

研究软件路线也可考察 JOSS，但其关注成熟的研究软件，有公开活跃开发超过六个月、研究用途和实质工程贡献等条件，不能视为任何新仓库都可立即选择的保底路线。[JOSS 投稿要求](https://joss.readthedocs.io/en/latest/submitting.html)。

本次尚未审计仓库公开开发历史、全部发布条件或成熟度。因此目前适合说“有可以发展成论文的贡献方向，基础功能重叠较高，需要补齐对照证据”，不适合说“现有创新点已经足够发表”。

## 调研限制

- 这是针对近邻先例的筛查；并未穷尽反应网络、时序图、原子谱系和化学信息可视化全部文献，不能下“首个”结论。
- ACS/PMC 部分直接打开被限制，ACS Omega 方法细节通过一手页面的搜索索引读取；ReaxANA 主要依据出版页摘要和作者代码，未取得全部主文与 SI。正式稿件前应固定全文及软件版本重新核对。
- 本次未运行竞争软件、未独立复核它们的性能数字。公开 README 宣称与源码确认、实际运行必须分级表述。
- 不能把未找到某项说明写成“该工具没有此能力”，也不能把当前 Scope 契约或讨论草案写成已通过验收的结果。
