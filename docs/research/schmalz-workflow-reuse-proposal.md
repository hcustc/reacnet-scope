## 当前起点

最新 [ADR-0020](../adr/0020-center-dash-on-candidate-step-occurrences.md) 与[开发记录](../target-species-workflow-development-plan.md)已把主线接通为：目标 Species → 候选步骤 → 多个独立 Reaction Occurrences → 所选实例结构/轨迹 → 证据与 DFT 初始几何导出。当前代码包含实例分页、稳定事件交接和返回上下文。开发记录仍保留浏览器视觉与真实数据人工验收缺口；本次只做源码和文档检查，没有重新运行其中记录的测试。

因此，“提供多个实例浏览”“添加 DFT 初始结构导出”“实现跨重复模拟检出率”都不应再列成全新功能。当前可复用的基础包括：

- `path_search.py` / `path_search_services.py`：有界候选检索、步骤实例、来源修订检查。
- `candidate_evidence.py`：返回/往返证据及折叠统计；保留原始与筛选口径。
- `analysis_services.py::rank_representative_events`：按精确关联、前后帧可用性及键变化给出实例推荐理由，目前主要是证据可检查性。
- `dft_geometry.py` / `reaction_readiness.py`：精确前后帧、完整参与分子、稳定 Atom ID、PBC 和单位检查，支持可审计的外部计算交接。
- `batch_compare.py`：有方向且保留计量的反应匹配、检出率、正反向/净 TP 与重复统计。无需重建这一层。

设计基准目前冻结 Path Verification 和 QC 交接扩展；下述 QC 回填与后端接入属于未来范围提案，实施时需同步相应契约。

## 1. 复用外部量化工作流，增加结果回填

**文献事实。** 原文已有多层级路径精化；ChemTraYzer 3 官方 API 提供 TS、IRC、NEB-TS 调查及优化失败、错误反应等状态。其文档明确说明：未要求 IRC 时，成功 TS 优化可以直接关联到预期反应。因此工具支持什么与一次任务实际做过什么不同。[原文](https://doi.org/10.1002/kin.21719)；[CTY3 QM API](https://ltt.pages.git-ce.rwth-aachen.de/ChemTraYzer/reference/qm.html)。

**建议复用。** 将 CTY3 等作为外部计算后端候选，先用现有交接包验证一例输入输出适配。接入前需要核对原子顺序、电子态、几何单位及输出身份；当前尚不能称为即插即用。代码搬用和依赖引入需另行核查许可证与版本兼容性。

**Scope 应补的能力。** 建立“原始事件—导出几何—每次计算尝试—实际得到的反应”的回填记录。每次尝试至少保存：

- 来源修订、Replicate、event_id、原子映射和导出参数。
- 计算方法/软件版本、电子态、环境模型与构象来源。
- 收敛结果、频率是否执行、虚频及对应振动模式、IRC 是否执行及实际端点。
- 优化后端点改变、不同反应、未收敛等明确失败或不一致原因；原始输出位置或校验信息。
- 能量类型、参考态、单位和可比较条件；电子能、焓、自由能分别表达。

现有 `ready` 仍仅指具备交接条件。QC 返回结果使用独立状态；一个实例得到某种电子态下的支持，不自动给整个 Reaction Type 或完整 Candidate 发放“已验证”结论。对于无势垒或涉及多电子态的情况，单一 TS/IRC 模板不足，应保留其验证限制。

**首个验收样例。** 同一候选步骤关联两个计算尝试：一个 TS 收敛但未执行 IRC；另一个 IRC 连接到不同端点。界面应准确展示二者差别，并能返回各自的原始事件。计算器放在外部，Scope 首先完成导出和结果导入。

## 2. 从“有可用坐标”改进到“挑选多样、可解释的计算样本”

**已有能力。** 实例浏览和证据可用性推荐已经存在，但目前排序不等于构象覆盖，也不等于反应的化学可信度。

**建议。** 在同一步骤内，先按精确键变化、参与分子和电子态信息区分实例，再对有可比较几何的实例描述反应中心、接触构型和构象差异，帮助研究者选出少量代表样本。每个样本显示入选理由、来源和未覆盖范围。几何比较仅服务于选择，不能从坐标生成第二套 RNG 反应事实。

自由基、环境参与和可能包含多步变化的事件应显式标记；不能靠一个按元素组成或分子式归并的样本代表所有事件。电子态不明时保留待确认，不自动猜测多重度。

多层级筛选可以复用原文思路，但半经验/力场能垒适合作为研究排序信号。若要硬性淘汰候选，需先用高层级计算抽查淘汰集、评估漏检风险，不直接移植论文某一体系的阈值。这是方法建议，而非已有算法的性能声明。[原文](https://doi.org/10.1002/kin.21719)。

**验收。** 固定候选与计算预算，比较“取前几个事件”“按频次选样”“按几何差异选样”的独特端点/构象覆盖、实际目标反应确认数、失败原因和成本。小样本的成功率不直接外推全网。

## 3. 借鉴 ReaxANA 去振荡，改善可解释性和参数稳健性

**文献事实。** ReaxANA 代码含时间窗口驱动的振荡消除和节点收缩。[官方项目](https://github.com/XinChenQC/ReaxANA)；[振荡规则](https://github.com/XinChenQC/ReaxANA/blob/main/tool_removeOscill.py)。

**建议复用。** 借鉴规则分类和时间窗口的分析思想，在现有 RNG 事件索引及返回证据上构建可撤销视图。Scope 不需要接入其坐标成键/反应重建部分。

**进一步改进。** 为每条被折叠的证据显示对应返回事件、规则和窗口；提供原始/筛选视图对照及参数敏感性报告。区分“当前参数下没有留下支持事件”和“原始数据未观察到”。持续性与频数可作为筛选维度，但短寿命或低频本身不能证明反应无意义。新规则应先证明不会隐藏研究对象再进入默认配置。

**验收。** 固定来源与搜索预算，对照 raw 和若干窗口下的保留步骤、实例及候选；显示变化由哪个条件产生，同时报告查询是否截断。只有时间映射已确认时才将帧窗口表达为物理时间。较重的派生证据构建放在 preparation，不在在线查询中扫描全部轨迹。

## 4. 借鉴 AUTOGRAPH，解释完整共同反应物依赖

**文献事实。** AUTOGRAPH 提供局部展开、筛选和路径展示；其路径代码检查其他反应物是否在已出现物种集合中。该集合不是会消耗分子数的库存，也不证明事件时间或原子连续性。[官方代码](https://github.com/failip/autograph)；[路径算法](https://github.com/failip/autograph/blob/main/src/lib/graphs/graph.ts)。

**建议复用。** 将其局部展开、可撤销过滤、共同反应物说明用于现有候选工作区，优先改善阅读一条路线所需的信息。无需为这些能力替换 Dash 或先做 3D 图。

**进一步改进。** 主链 A→B 的步骤应展开为完整反应 A+X→B+Y，显示 X 是否来自指定进料、当前展示的其他分支，或尚未在本视图追查。不同状态只是来源解释，不能把“本图未展示 X 的生成路线”当作缺少真实反应证据。

“给定进料约束下探索可供给的网络”可以是另一个显式查询选项。它不能默认改变已有 Candidate 的存在规则，因为候选步骤本来允许由不同实例支持，而共反应物可以来自其他分支。完整计量和具体发生历史仍须独立表达。

### 与当前反应路径图的具体对照

2026-09-22 补充：对照当前 Scope 源码与本次文献研究保存的 AUTOGRAPH 官方源码快照（树 SHA `c99530f88b084b54f857b9d36613a4e93962bc36`）。此次没有进行两套界面的浏览器实测；不把源码快照等同于期刊发表时版本。

二者都采用物种节点和反应节点，属于用二部图表达反应关系的共同思路，也共同服务于反应网络探索。根据用户对研究场景的明确补充，Scope 的具体入口来自网络规模大、实验已提供关注对象这两个条件，应定位为围绕实验目标的反应网络探索。不能把“AUTOGRAPH 探索网络、Scope 只比较候选和检查事件”当作产品目的的本质区别；后者是 Scope 当前实现的操作组织方式。

下表描述当前实现、约束和证据能力的差别，不把这些差别固定为未来产品边界。

| 比较项 | AUTOGRAPH 源码快照 | Scope 当前候选路径图 |
| --- | --- | --- |
| 图的输入与范围 | 导入 JSON/CHEMKIN 反应网络，按起始物种和规则局部展开 | 对当前查询已返回的候选路线取合并视图；图组件不另行搜索 |
| 反应节点的连接 | 连接输入网络中反应的各反应物和产物 | 主图只连接 carried_from → 步骤 → carried_to；完整反应在详情中保留 |
| 节点身份 | 按输入网络的物种和反应节点 ID | 物种按精确 RNG 身份；步骤按完整有向反应及两端载体共同确定 |
| 路径算法 | 带依赖检查的 adapted Dijkstra；累加反应权重，缺省为 1 | 有界、步数优先的候选检索；每一步需有事件内最大原子继承支持，允许并列分支 |
| 共反应物 | 检查算法维护的已出现物种集合；不实现数量消耗和时间连续性 | 保留完整上下文，但默认不要求本条主线负责生成所有共反应物 |
| 布局与结构 | 三维力导向布局，可用 XYZ 显示分子与帧 | 稳定的从左向右二维布局，结构卡片与菱形步骤；精确事件几何通过实例下钻 |
| 点击后的主要用途 | 网络搜索、路径高亮、过滤/撤销、展开及结构展示 | 定位已有路线和步骤，再选择具体 event_id，查看前后结构与轨迹、导出证据 |

AUTOGRAPH 的代码依据：[图组件](https://github.com/failip/autograph/blob/c99530f88b084b54f857b9d36613a4e93962bc36/src/lib/graphs/Graph.svelte)、[路径算法](https://github.com/failip/autograph/blob/c99530f88b084b54f857b9d36613a4e93962bc36/src/lib/graphs/graph.ts)、[输入入口](https://github.com/failip/autograph/blob/c99530f88b084b54f857b9d36613a4e93962bc36/src/routes/+page.svelte)。Scope 依据：`scripts/webapp_dash/candidate_graph.py`、`scripts/webapp_dash/candidate_workbench.py`、`reacnet_scope/path_search.py`、`tests/test_candidate_graph.py`。

例如完整反应为 A+X→B+Y，若候选沿 A→B 继续，Scope 主图只画这条载体分支，而 X/Y 在完整反应详情中。这个投影减少图中参与物种数量，也可能让用户忽略共反应物。可研究点击步骤后展开 X/Y 的局部上下文，以视觉样式区分主线和参与物种；上下文边不能自动成为新候选步骤。

Scope 的合并图保留每个节点/步骤所属的原始候选，避免把视觉上可拼接的路线当作已返回的新候选。共享步骤的支持次数不按经过它的路线数相加。图上的二维位置不表示反应时间；AUTOGRAPH 的三维位置来自布局，也不是体系中分子的真实空间位置。两者的路径都不能仅凭图连通性确认为完整机理。

优先借鉴完整参与物种的局部展开、可撤销过滤和依赖说明。三维网络展示是可选呈现方式，目前没有比较实验表明它会改善 Scope 的路线对照和事件检查任务。

这一定位对后续设计的含义是：候选路线可以作为进入目标相关子网的入口，用户应能继续追查前驱物、竞争支路和共同反应物，逐步调整探索范围。当前返回候选的并集只是一个有查询约束的视图，不等于目标相关网络的全貌。“展开完整反应参与者”“查询更多邻接反应”“重新搜索候选”需要保持清楚的操作含义，并沿用有界索引读取和来源记录。这里记录探索方向，不表示当前图已具备这些扩展能力，也不改变 Candidate 与连续历史的既有证据区别。

## 5. 复用 Batch Compare，增加步骤级可重复性和条件比较

**文献事实。** 2026 超图挖掘论文用包含某个反应组合的独立模拟数定义支持度，并做条件比较、多重检验与量化精化；组合共现不要求同一分子依次经历全部步骤。它是 AUTOGRAPH 的后续关联文献，非 Schmalz 原文的直接引文。[全文](https://pmc.ncbi.nlm.nih.gov/articles/PMC12937057/)；[可机器读取全文](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC12937057/fullTextXML)。

**建议复用。** 首先把已有检出率/重复统计连到候选步骤。例如并列显示“总共观察 100 次”和“在确认可比的 10 次独立模拟中有 2 次检出”，而不是用总次数替代重复支持。

**进一步改进。**

- 每一步、反应组合共现和连续分子历史分开统计；各步骤都常见不保证整条路线被一个实例走过。
- 保留未检出、来源缺失、查询预算不足等差别，不能把没有分析完的来源计作阴性。
- 沿用已确认的条件、Replicate、RNG 处理口径；一条轨迹切成多段不自动成为独立重复。
- 再考虑条件效应量和显著性；Fisher 等方法仅用于满足独立性和可比性前提的问题。不要把增强采样频次解释为真实动力学速率。
- 最后才评估目标子网内的离线反应组合挖掘。统计结果服务研究优先级，不决定候选存在或连续历史是否成立。

CTY-TAD/PESmapping 对探索盲区的比较还启发“共同/独有通道及采样方法说明”，避免把单一方法的未发现解释为不存在。[作者团队后续论文](https://doi.org/10.1016/j.comptc.2025.115461)。

## 6. 原文的参考机理匹配，适合形成新增通道清单

**文献事实。** Schmalz 原文把 MD 网络与参考机理对照，再筛选需要计算研究的路径。[原文](https://doi.org/10.1002/kin.21719)。

**建议。** 导入带版本和来源的参考机理，建立其结构/反应身份与 RNG 身份之间的显式映射，显示已匹配、参考机理未包含、映射不确定等状态。必须保留方向、计量、异构体与参考机理表达方式的差别，允许人工确认有歧义的映射。参考机理未包含不等于文献未知或发现新机理。

可再增加断裂、抽氢、加成、环化等可解释反应家族标签，允许未分类或多标签；精确 Reaction Type 身份保持独立。博士论文中的局部模板分类提供了具体思路，同时展示了覆盖不全及复合事件限制。[机构全文](https://publications.rwth-aachen.de/record/1025143/files/1025143.pdf)。

这能让研究者组合查询“参考机理未包含 + 多个独立模拟支持 + 有可导出实例 + 尚缺 QC 结果”的通道。优先级由这些可解释维度表达，暂不压缩成一个含义不清的综合科学可信度分数。

## 围绕研究者选定目标的功能讨论

用户进一步明确：实验分析由研究者完成，然后使用 Scope 寻找机理解释。因此本轮以研究者选定的目标 Species 为起点，不围绕实验数据格式、峰归属或异构体鉴定增加工作流。软件保留一般物种检索和精确身份选择即可。

以下是讨论中的功能拆分，尚未成为实现承诺或正式契约。

| 功能 | 可复用的基础 | 需要继续开发的部分 | 建议顺序 |
| --- | --- | --- | --- |
| 完整反应上下文 | AUTOGRAPH 的参与物种连接；Scope 已有完整反应式和参与者详情 | 点击步骤后展开/收起共反应物和其他产物；区分主线与上下文；保留计量 | 第一批 |
| 围绕目标局部展开 | AUTOGRAPH 的逐层展开；Scope 生成/消耗通道和已发布证据索引 | 从目标查看直接前驱物，再按需查上游或下游；每次有界读取，能继续取回尚未展示的邻接结果 | 第一批 |
| 探索过程的撤销与恢复 | AUTOGRAPH 撤销模式；Scope 已有路线选择和返回上下文 | 撤销一次展开或筛选、固定关注节点、保持已有布局；随后支持保存和恢复探索视图及来源修订 | 第一批先做撤销与固定，保存恢复随后 |
| 从局部网络选择和比较路线 | Scope 当前候选搜索、多路线高亮、共享步骤比较 | 在探索中选起点/目标重新查询；后续研究途经/排除条件，结果仍保留独立候选身份和预算状态 | 第二批 |
| 可解释筛选与折叠 | AUTOGRAPH 过滤交互、ReaxANA 规则思想、Scope 原始/往返折叠证据 | 区分仅改变显示的隐藏和会改变搜索结果的约束；展示隐藏原因，允许恢复并比较不同参数 | 与第一、二批逐步结合 |
| 图上的证据比较 | Scope 实例下钻、Batch Compare、来源/修订检查 | 按需展示跨重复支持、筛选前后支持、计算覆盖；明确不同统计的分母与证据层级 | 第二批 |
| 从选定反应进入量化研究 | Scope 几何交接，CTY3 等外部后端 | 代表实例选择、外部计算结果回填、失败记录和实际端点核对 | 后续专题，需调整 QC 扩展范围 |

从目标向上游查找是对已观测反应的反向检索，反应箭头仍保持原始化学方向，不推导未观察到的逆反应。完整反应参与网络与当前 Candidate 的载体投影需分别表达：主导原子继承适合限定候选主线，却不能成为所有参与物种是否出现在探索视图中的唯一条件，否则研究者关注的较小产物可能被隐藏。完整网络展开本身不把这些上下文连接自动认定为新的 Candidate。

对应的使用场景是：研究者选择产物 P → 查看直接生成反应 → 展开某个前驱物的上游 → 展开一个反应的全部参与者 → 固定关注分支并收起其他分支 → 搜索或比较相关候选 → 打开具体实例核查 → 返回原视图。新增功能应沿这条链路组织，沿用已有证据查看和导出。

代码复用方面，AUTOGRAPH 快照的 [LICENSE](https://github.com/failip/autograph/blob/c99530f88b084b54f857b9d36613a4e93962bc36/LICENSE) 已实际读取，标为 MIT；[依赖清单](https://github.com/failip/autograph/blob/c99530f88b084b54f857b9d36613a4e93962bc36/package.json) 使用 Svelte、Three.js 和 ngraph。Scope 当前使用 Dash/Cytoscape，因而优先复用设计及可独立适配的逻辑；尚未验证任何模块可直接移植，也未决定更换前端。直接采用其源码时应保留许可证要求的声明。

## 建议顺序

1. 完成现有主线剩余验收，同时优先研究“目标局部展开＋完整反应参与者展开＋撤销/固定”。先让研究者能围绕目标连续探索。
2. 完善受控路径搜索、筛选解释、跨重复证据比较和探索视图保存；复用现有实例下钻与导出，不再建设重复入口。
3. 当工作重点进入量化研究时，推进代表实例选择和 QC 结果回填；先完成一次外部计算的可追溯回填，再扩大后端自动化。该阶段需要调整当前 QC 扩展冻结范围。
4. 随研究需求增加参考机理映射、反应家族标签和目标子网的离线模式挖掘。

最值得作为方法学评估的问题是：在相同数据和量化预算下，是否能减少无效计算、发现更多不同且实际得到计算支持的通道，并解释每次筛选和验证失败。文献与源码阅读支持上述研发方向；目前没有实验结果证明这套组合优于既有工具。

## 初步 PR 拆分草案

2026-09-22：以下保留需求核对前提出的四个工程切片，实际工单归属与拆分以本节之前的需求核对为准；不强制创建四个独立 Issue 或四个 PR。尚未创建 Issue/PR，也未将研究提案改成已接受契约。用户关于时间先后的问题按现有 Candidate / Continuous MD Support 契约处理：具体事件链要求时间严格递增和分子/原子承接，网络候选不默认要求整条连续链。

### PR 1：在候选图中展开完整反应参与者

- 用户行为：点击已有步骤，展开/收起共反应物与其他产物，并继续查看步骤及具体实例。
- 复用现有完整反应数据、结构卡片、路线成员和事件下钻。保持完整有向 Reaction Type 与 carried pair 定义的候选步骤身份；上下文连接有独立展示角色。
- 验收：A+X→B+Y 可以从 A→B 主线展开 X/Y；计量重复与同式异构不丢失；共享参与者在某一步收起后仍可被其他展开步骤引用；共享步骤计数不累加；上下文边不会被解读为新候选或连续事件链。
- 范围限于已有结果的展示与交互，不查询更多邻接反应。同步必要图语义说明，不改变 Candidate 的成立条件。

### PR 2：从目标物种按需展开上游和下游反应

- 用户行为：仅选定目标 Species，即可查看直接生成反应，并对前驱物继续展开；也可查看某物种的消耗反应。
- 复用通道查询的领域逻辑和已发布证据，补充适合大数据的有界邻接查询；必要的索引派生只在 preparation 完成。完整参与网络不会仅按候选载体目录裁剪。
- 局部探索结果与已有候选结果分别保存身份、来源修订和完成状态，允许选择端点调用现有候选搜索。展开上下文本身不产生 Candidate。
- 验收：仅有目标也能进入；小分子产物的生成反应可见；反向查询仍保持已观测箭头方向；大节点分页/继续展开不漏报截断；缺索引与无结果可区分；源修订变化、数据集切换和迟到结果不能串入当前图。
- 同步核心查询、必要公共入口、Dash、导出和契约文档，以一个可用行为交付。PR 1 的参与者展示可作为基础。

### PR 3：控制并撤销局部探索操作

- 用户行为：撤销一次展开/隐藏，固定关注节点或分支，收起不关注内容，再恢复视图。
- 第一版管理当前会话内的探索；保存到磁盘和跨版本恢复留给后续明确格式的改动。
- 复用当前选择、稳定身份和返回上下文。一次撤销恢复此前的选择与展开状态，不删除证据，不把图上隐藏自动变成搜索条件。
- 验收：连续展开两层后可逐次撤销；共享节点按仍有效的展开来源保留；恢复不改变计数和候选身份；切换数据集不恢复旧会话结果；新增节点尽量保持已有关注区域的位置。
- 依赖 PR 2，并包含其新探索动作所需的状态回归。PR 2 本身仍需基本展开/收起和状态安全，不把正确性留到 PR 3。

### PR 4：展示时间分布和连续发生证据

- 用户行为：从候选步骤查看已有发生时间分布；对选定路线运行已有连续性检查；查看或过滤本次已检查且找到连续事件链的路线。
- 复用现有时间汇总、选择性检查及实例交接。保留未检查、找到实例、未观察到与证据不足；显示实际检查范围，不能将未检查的候选当作不支持。
- 验收反例：下游早于上游不能作为连续链；时间递增但分子不同不通过；不能跳过先前消耗；同 Transition 内无法排序；缺少间隔内连续性证明仍为不确定。找到的链应可定位各事件，保持原候选查询结果和身份。
- 首轮不新增全网事件链枚举、不默认设最大等待时间，不扩大为修复全部跨帧连续性能力。分析帧和物理时间严格区分，换算要求已确认映射。
- “模拟时间窗口改变整个探索/搜索结果”需要另一个范围：确定计数、参与步骤、折叠边界及导出的窗口语义。首轮时间证据展示不暗中引入这一契约。
- 可基于现有候选工作流独立推进，无需等待 PR 3。

若采用上述工程切片，顺序可为 PR 1 → PR 2 → PR 3；PR 2/3 服务同一个目标局部探索需求，必要时合并交付。PR 4 先对照 #25/#26 的实际剩余范围，不预先安排为新的独立工单。
