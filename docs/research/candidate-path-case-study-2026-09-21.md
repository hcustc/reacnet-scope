# 氯酚候选路径案例：短暂往返如何被拼成生成路线

日期：2026-09-21。用户问题：截图中检索得到的路径看起来不合理，能否由实际数据判断 Scope 检索方法存在什么问题？

## 结论

**本例确实暴露了路径筛选质量问题。首步的全部支持事件都立即复原，第二步的全部支持事件也是其他分子的短暂开环后的闭环；Scope 把这些事件按代表 Species 拼接成了三步生成路线。** 这不是仅凭结构图做出的判断。

同时有两个独立问题：`miso=1` 代表图未显示末步真实的 C=O；默认搜索预算还漏掉同为三步的路线。不能将所有问题都归因于 BFS，也不能通过增加“候选不是机理”的提示解决。

本研究只读使用已有 RNG、Scope 索引与有界轨迹帧，没有重新运行 RNG、MD 或 DFT，没有改变科学契约和应用代码。

## 1. 截图首步：两个事件都只产生一个采样帧的片段

| 首步 event ID | 首步 Transition | 第一次后续消耗 | 后续行为 | 返回时精确键集合 |
|---|---:|---:|---|---|
| `rngevt_10744_fe7574f5f963` | 10744 | 10745 | 原 CH 与开链片段重新结合为原氯酚；同一批原子 | 连接关系恢复，部分键级不同 |
| `rngevt_130119_2a03908ac21f` | 130119 | 130120 | 原 CH 与开链片段重新结合为原氯酚；同一批原子 | 完全恢复 |

两个后续事件为 `rngevt_10745_e3ade86f0748`、`rngevt_130120_5cd33c71cafd`。Scope 已发布 `continuity_links` 指向这两个首次消耗，没有先跳过其他反应再选择有利连接。

因此，开链片段在保存的轨迹中仅占据一个采样帧。10 fs 是采样间隔/网格上的占有尺度，不是已经精确确定的连续时间寿命。形成和消耗发生在相邻 Transition 内。

第一例不能声称精确键级完全复原；按 Scope 严格定义，不能仅凭相同标签和原子就把它与第二例一起称作完全相同的 Fast Recrossing Episode。两例都可以明确称为同原子的连接拓扑往返。

### 局部几何交叉检查

通过已有轨迹字节索引读取每例周围五帧，用 Scope 帧解析与 ASE 最小镜像距离核对记录中断开的两个 C–C 原子对。单位由 MD 输入的 `units metal` 确认为 Å；atom type 映射来源是同一输入和 RNG 参数。坐标只提供几何旁证，不覆盖 RNG 键认定。

| 片段占据的帧 | 被记录断开的 C–C 对 | 该帧距离 / Å |
|---:|---|---:|
| 10745 | 898–903 / 902–903 | 1.543 / 1.645 |
| 130120 | 534–539 / 538–539 | 1.376 / 1.386 |

前后五帧的这四对距离均约 1.26–1.65 Å，未呈现 CH 片段远离原骨架的几何过程。**结合单帧出现、立即原子重组及未启用 HMM，优先怀疑短暂判键/拓扑波动有实证理由。** 但这不是已经定位到某个 RNG 判键函数的缺陷，也不能只凭距离证明完整电子结构或势函数正确；本研究没有重新执行反应识别。

## 2. “77 次闭环”全部是其他分子的短暂往返

第二步的 77 个支持事件只涉及四组完整原子集合，事件数分别为 27、7、26、17。这些集合与首步两个开链产物的原子集合**完全不相交**。

对每个闭环事件，以其全部 11 个原子查询最近的前序事件、排除最近 Transition 的多个事件歧义，再核对完整参与者，得到：

- 77/77 的最近前序事件都是同一批原子的反向开环。
- 73 次开环到闭环相隔 1 个采样间隔；3 次相隔 2 个；1 次相隔 3 个，即网格尺度 10、20、30 fs。
- 77 次均返回原环的相同 Species、原子与连接关系；其中 43 次连精确键级集合也恢复，34 次存在键级差异。
- 这些是重复开闭环事件数，不是 77 次独立的、从起始氯酚生成目标五元环的证据。

这意味着截图三步链的第一、第二步之间，没有一条由它们所列支持事件组成的连续分子链。该判断来自穷尽首步的两个支持事件及第二步的全部 77 个支持事件，范围限于这两条具体路线，不能扩展为目标在整个数据集中不存在其他生成历史。

用实例下标表示实际记录：

```text
氯酚₁ → 开链₁ + CH₁ → 氯酚₁           （一帧后复原）
五元环₂ → 开链₂ → 五元环₂             （一至三帧后闭环）
五元环₃ + Cl/O₂ → 目标₃ + HCl/HOO     （独立末步记录）

按代表 Species 合并后的检索输出：
氯酚 → 开链 → 五元环 → 目标
```

第二步的四组实例中有一组与 O₂ 末步的载体原子相符；这不补上第一步已经断开的来源，也不自动证明第二、三步之间没有其他消耗或中断。

## 3. 图中的“奇怪末端结构”确有代表显示因素

两种末步的目标产物中，原始 RNG 均记录了 `31-38-2`，即碳 31 与氧 38 的双键。截图及代表标签却显示单键 C–O：

```text
[H][C]1[C]([H])[C]([O])[C]([Cl])[C]1[H]
```

因此不能把代表图上的单键氧和自由基点直接作为这两个真实事件的电子结构，再据此断言末步不合理。`miso=1` 下同连接网络的键级状态被合并，本例的显示损失已由原始键集合证实。

这也修正了仅凭截图评估整条路线的局限：**短暂裂解、跨实例拼接、代表结构显示，是同时存在但不同的问题。** 用代表图的不足解释首步与第二步的实际往返，同样不成立。

## 4. 增加搜索预算没有解决事件质量问题

保持 exact 起终点和 6 步上限，执行 12 组有界查询。详见 [敏感性研究](candidate-search-sensitivity-2026-09-21.md)；完整查询结果保存在不随仓库分发的本地 JSON 中。

| 展开预算 | 待搜索分支预算 | 结果 |
|---:|---:|---|
| 2000 | 5000 | 2 条三步路线 |
| 2000 | 20000 | 6 条三步路线 |
| 20000 | 5000 | 2 条三步、18 条六步 |
| 20000 | 20000 | 6 条三步、14 条五步 |

所有查询仍截断；差异不是时间超限造成。仅增加展开预算不能恢复此前被 frontier 裁掉的短前缀。

增加分支容量得到的六条三步路线，共有三个不同精确开链中间体，其首步支持数为 2、2、3。额外五个脱 CH 事件也已核查：**七个首步支持事件全部在下一 Transition 同原子重组回氯酚，五个完全恢复键级、两个仅恢复连接拓扑。** 所以本案例中“搜到更多三步路线”没有消除问题，只找到了更多同类短暂往返。

## 5. 对 Scope 方法的判断与改进顺序

现有实现忠实执行 ADR-0013/15/16：每步局部原子继承、不同事件按 Species 连接、按步数与精确身份展开。抽查结果未发现 Scope 把本例原始事件反应式、参与原子或键集合读错。问题主要是**现有资格条件未区分短暂返回与生成进展，再把独立步骤拼接为路线**。方法审查细节见 [源码审查](candidate-search-method-audit.md)。

建议按以下顺序设计修改；这些是研究建议，尚未改变有效契约：

1. **先加入事件后续去向与占有时间事实。** 对主线产物记录首次消耗、单帧占有、同原子返回、仅拓扑返回/精确键级返回。对“全部支持事件都立即复原”的步骤给出明确质量标记，不能只与普通生成步骤同等展示。保留原始记录，避免直接删除所有低频事件。
2. **区分形成与重新闭环。** 本例 77 次应连同“全部有最近反向开环”展示；计数不能被理解为净形成或独立分子数。频次优先甚至可能放大往返，因此仅加频次阈值无效。
3. **让结构图能切换到具体事件键状态。** 保留代表身份用于网络检索，同时明确具体事件的键级；不能用代表图代替事件结构。本例真实 C=O 应可见。
4. **给网络候选补上选择性连续支持检查。** 本例首步的第一次消耗已经否定了所列三步连续实现。检查应报告事实，而非强行用同名中间体跳过复原。网络候选与连续支持可以继续分离，但默认结果应让用户看到这种负面证据。
5. **最后调整预算和检索优先级。** 将事件质量与用户选择的证据条件纳入有界搜索的设计评估，避免字典序和短跳数决定有限预算的全部曝光。尚不建议发明未经验证的综合“化学分数”，也不建议以加大预算作为修复。
