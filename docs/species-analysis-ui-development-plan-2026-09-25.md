# 对象中心的多入口分析与事件详情：开发交接方案

日期：2026-09-25

状态：第二版；2026-09-26 已在当前工作区实施，验收结果见文末实施记录。

用途：在新对话中实施本方案。第二版替代第一版“RNG 数据／物种分析／收起的工具菜单”
的导航决定，采用“RNG 数据／物种／反应／演化／事件”五个平级入口；保留对象内分析、
共用详情、工具可预填也可独立使用的原则。保留原文件名，避免已有交接链接失效。
已同步正式基准与 ADR；本文保留交接和验收依据，不替代仍有效的科学契约。

## 1. 要解决的问题

当前“物种发现／物种研究／证据核查”一级导航，以及“研究概览、路线探索、相关反应与
反应检索、丰度趋势、事件检索、反应对比”等任务导航，让用户先理解功能分类，再找操作。
研究物种摘要与快捷入口还会在横幅、概览和任务导航中重复出现。

物种起点的一条典型流程是：

> 检索并选中精确物种 A → 对 A 查路线、相关反应或丰度 → 在结果中选择步骤／反应 →
> 查看具体事件 → 展开事件详情及证据核查 → 返回原结果位置。

同时支持从反应检索、丰度排行、元素分布和事件检索直接进入分析。上述流程不是其他入口
的前置步骤；不能把“对象中心”实现成“所有操作必须先选物种”。

### 设计原则

1. **对象详情承载分析。** 当前查看的精确 Species、Reaction Type 或 Occurrence 决定详情
   的输入。用户在对象详情中发起分析，结果在当前上下文内显示。
2. **多入口保持独立。** 有反应式就从反应开始，有事件问题就从事件开始；演化可以先查看
   当前数据的丰度和元素分布，再选择值得深入的物种。
3. **详情和核查可复用。** 同一事件从路线、反应或事件列表打开时使用同一套详情与核查。
4. **分析能力与入口解耦。** 查询接收明确的来源、精确目标和参数，既能预填也能手动填写；
   分析核心不依赖“用户先访问了哪个页面”。返回位置和入口类型由 Dash 展示层管理。

“演化”是围绕丰度与分布随时间变化的观察入口，本期不新增名为“演化特征”的科学身份
或自动阶段判定算法。参考对象详情与上下文下钻的交互模式，不需要复制某个外部产品布局。

## 2. 最终界面方案

### 2.1 顶部入口

一级导航围绕对象与观察问题组织：

```text
RNG 数据    物种    反应    演化    事件
```

| 入口 | 主要职责 | 可以从哪里开始 |
| --- | --- | --- |
| RNG 数据 | 当前数据、导入列表、切换与准备任务 | 文件夹与已导入来源 |
| 物种 | 精确物种检索、物种详情、路线／直接反应／趋势结果 | 查询物种；其他结果中的精确物种；直接填写路线起终点 |
| 反应 | Reaction Type 检索、反应详情、对应事件和多来源反应对比 | 反应式或精确反应类型，无需研究物种 |
| 演化 | 丰度排行、丰度趋势、元素分布及物种多来源对比 | 当前数据的丰度证据；用户选择的物种和比较来源 |
| 事件 | 独立事件查询、事件列表和共用事件详情 | 现有支持的事件查询条件，无需研究物种 |

撤下“物种发现／物种研究／证据核查”的旧分组和横向任务排。“研究概览”不再单独占
入口，其身份和统计内容回到物种详情。默认不再加全局“工具”菜单；各入口提供本页相关
的查询方式或显示模式，不复制原来混合六七种任务的导航。

独立路线入口仍需可发现：在物种页的检索空态或相关操作区提供“直接探索路线”，打开
同一候选查询能力，由用户填写起点／终点，不要求先建立研究 Species。独立丰度查询在
演化页填写目标；反应式和事件查询分别从反应、事件页进入。

物种多来源对比继续作为丰度分析的模式；反应多来源对比属于反应页。不重新创建单独的
batch-compare 页面，也不取消现有比较能力。演化页可有必要的“排行／趋势／元素分布”
视图切换；这属于同一问题范围内的选择，不是把所有工具重新堆进一个容器。

### 2.2 物种页内的显示顺序

采用同一主内容区内的阶段切换，不把搜索、全部分析结果和事件核查堆成一个长页面：

| 当前阶段 | 显示内容 | 后续操作 |
| --- | --- | --- |
| 检索 | 分子式／精确结构／质量查询，结果列表，必要的异构体下钻和结构预览 | 选中一个精确 Species |
| 物种详情 | 一份身份与结构摘要、已有生成／消耗统计，以及分析按钮 | 选择分析；返回检索 |
| 分析结果 | 保留精简的物种身份与返回入口，主要空间显示当前分析及必要参数 | 调整查询；下钻；选择另一分析 |
| 事件详情 | 显示选中的具体事件；需要时展开全宽核查 | 关闭／返回，恢复原结果位置 |

初始检索与预览可以上下排列；进入物种详情或分析结果后收起或替换检索区域。
“返回检索／更换物种”恢复检索条件、结果和已有选择，不因为显示切换而重新查询。
从其他入口打开物种时保留“返回反应／返回演化”等实际来处；返回本身不清除研究物种。

物种详情保留以下操作：

- 查生成路线：A 预填为终点，采用现有仅终点前驱模式。
- 看后续转化：A 预填为起点，采用现有仅起点模式。
- 相关反应：展示直接生成／消耗 A 的一步通道。
- 丰度趋势：将精确 A 带入现有趋势分析。
- 指定另一端的双端路线搜索仍可在路线查询区使用，不减少 ADR-0026 的三种模式。

从详情发起后用该详情对象作为明确目标，直接显示相应分析；需要的查询参数就地可见或展开。
未修改的预填条件保持明确。已有结果的返回与重开不自动重跑，用户显式提交才发起新查询；既有 preparation
完成后恢复已提交请求的机制继续遵守原有身份约束。

物种身份只显示一份必要摘要，取消重复概览和横幅。趋势使用完整结果区域，不要求缩成
小弹窗；路线、直接反应、趋势不同时铺满屏幕。不新增另一排常驻工具选项卡。

### 2.3 事件列表与证据核查

以下入口打开同一套事件详情行为：

1. 路线步骤 → 该步骤的支持事件列表 → 选中的事件。
2. 直接生成／消耗通道或独立反应检索结果 → 对应事件列表 → 选中的事件。
3. 独立事件检索 → 查询结果中的事件。

路线步骤的事件列表留在路线结果中；反应的事件列表也留在相应反应结果中。常规下钻不
要求先跳到一个空白“事件检索”页重新填写条件。

事件详情先显示身份、时间定位、参与者和可用的 RNG 前后键结构；可就地展示或使用抽屉。
局部轨迹、3D、事件包、DFT 初始几何和分子变化追踪按已有能力展开；需要大画布时使用
全宽模式。全宽模式有明确返回入口，并且仍属于这次事件下钻。

取消的是“证据核查”的独立导航入口，不删除任何现有核查、导出、单位确认或能力检查。
内部可暂时保留 trajectory 等标识承担展开视图，不要求先删除其全部布局和回调。

### 2.4 反应、演化和事件入口的职责

**反应页**保留反应式查询和精确 Reaction Type 选择。选中反应后就地展示反应物／产物、
可用统计与具体事件；有事件证据时可查看已有的发生时间分布并选择事件。多来源对比复用
现有来源选择、条件／Replicate 确认和统计结果，不把比较当成自动混合各来源的事件列表。
物种页的“相关反应”复用同一反应详情能力，但仍标明一步生成／消耗通道，结果留在该物种
上下文中。反应参与物种可打开精确物种详情，保留回到原反应的入口。

**演化页**先回答当前数据中哪些物种丰度突出、丰度和元素分布如何随时间变化。提供已有
丰度证据支持的排行、单／多物种趋势、元素分布及多来源物种对比。点排行中的精确物种，或
从元素分布下钻到精确结构后，可进入物种详情继续查路线、反应或趋势，并返回原分布位置。
只选中了分子式／元素分组时先解析到精确 Species，不能随意挑一个异构体进入分析。

**事件页**服务于直接找事件的问题，保留独立查询和结果列表。已知反应类型的查询、已有
反应时间分箱交接与从结果打开详情可复用；更广的时间／原子筛选按 §3 的能力清单实施，
不因为新增了页面名称就宣称完整支持。事件页与核查详情是不同职责：其他页面打开详情
时不必先经过事件页。

### 2.5 多入口交接和来源

- 当前来源下，从反应参与物种、丰度排行、元素分布打开 B，传递 B 的精确身份及来源到
  物种详情，随后对 B 的分析使用 B；不再要求用户回到搜索框重查。
- 这类详情浏览不自动替换已有研究 A。详情明确显示实际对象 B，需要时使用既有显式
  “设为研究物种”操作。对象详情的分析目标不能被全局研究 A 暗中覆盖。
- 同一工具在多个对象详情中复用；每个结果保存实际来源和输入，不能仅凭当前页面名称
  或全局选中物种解释旧结果。
- 比较结果中的物种可能来自非当前来源 Y。卡片明确标识 Y；普通单来源分析仍遵守
  Current Dataset 规则，提供显式“切换到此来源并分析”，成功后再交接目标。失败或取消
  保留原来源和比较位置；不隐式切换，也不能拿当前 X 的证据解释 Y 的对象。
- 核查和 DFT 初始几何来自一个精确事件及其来源；DFT 导出是用户按需执行的能力，不是
  所有浏览链的必经步骤，不意味着已经产生优化结构、过渡态或完整量化计算输入。

## 3. 范围与保留行为

### 本次要实现

- 调整五个平级入口、页面标题、当前入口高亮和数据页中的分析入口。
- 将现有物种详情、路线、直接反应和趋势组织为连贯的对象内分析流程。
- 建立反应、演化、事件独立入口及到物种详情的交接，补充演化页的现有丰度排行展示。
- 从所有现有事件入口复用事件详情与核查，支持准确返回。
- 保留工具的独立输入和运行方式，完善旧会话页面的恢复。
- 同步文档、回调测试和浏览器验收。

### 本次不扩展

- 不将反应检索、事件检索、反应对比强行合成一套新查询表单／结果 schema。
- 返回使用有界、会话内的位置链；不扩展成跨研究物种的完整历史管理、项目持久化或收藏系统。
- 不改变现有研究物种建立方式，不新增“必须点开始研究才建立身份”的前置步骤。
- 本期先交付下表中明确可复用的能力；广泛时间／原子筛选、时段统计等扩展列为单独的后续
  能力项，不能用前端筛选已加载一页结果冒充完整查询，也不把其语义设计藏进导航改造。
- 不新增后台索引、不改变科学算法、公共 CLI/API 或导出含义，不引入新的前端构建链。
- 不以把 page-species、page-reactions、page-trajectory 物理合成一个函数或文件为验收目标。

### 能力复用与后续扩展清单

| 设计中的能力 | 已核对的当前能力 | 本期交付与后续边界 |
| --- | --- | --- |
| 丰度排行 | `analysis_services.search_species_catalog` 可按丰度索引的 `total_count` 排序 | 本期在演化页提供展示与精确物种下钻；标注累计采样丰度及其记录范围，不称当前丰度、峰值或物理时间积分；复用有界索引读取，避免为展示扫描原始数据 |
| 丰度趋势／元素分布 | 已有索引、趋势／分布结果与分布下钻；趋势已有多来源模式 | 本期重组展示与交接，保留逐来源目标和时间口径；不顺带新增元素分布多来源界面 |
| 反应多来源对比 | 已有精确 Reaction Type、条件／Replicate 分组、检出率及正向／反向／净 TP 等统计 | 本期纳入反应页；显示真实指标名称。事件发生次数、每单位时间频率和 TP 不混称，新增窗口频率比较需另行定义完整观察窗与换算 |
| 按反应类型查事件 | `evidence_services.locate_rng_events` 接收完整反应式并查事件索引 | 本期保留独立查询并复用共用详情；分子式反应发现须先解析为精确 Reaction Type |
| 反应内时间窗事件 | `event_index.query_events_window` 已支持一个精确反应的半开时间窗 | 本期复用现有时间分布／分箱交接；它不等于“不给反应类型的全局时间检索” |
| 按参与原子查询 | 索引有 `query_nearest_atom_events`，语义为指定时刻前／后的最近相关区间 | 后续通用筛选需明确任一／全部原子、来源内原子身份、时间窗、分页和 unresolved 处理；不直接包装最近事件查询冒充所有匹配事件 |
| 时段分析／阶段性特征 | 现有趋势可观察时间变化，已有部分时间分箱能力 | “时段分析”尚未指定统计量；本期保留图表查看和已有窗口能力。新增窗口排名、阶段检测或阶段统计需单独定义并验证 |

后续能力项保留在计划中，不提前显示可执行但实际无效的控件。若后续任务选择实现它们，
先按 reacnet-analysis-contracts 明确问题、证据和输出；需要扩展离线索引时再使用
reacnet-evidence-indexing。科学规则在核心实现并由 Dash 调用，不能通过 UI 标签改变含义。

### 必须保留的语义

- 按当前 ADR-0027，物种检索中选中精确结构即建立研究 Species；分子式分组不是精确身份。
- 研究 A 时，查看中间物种 B、反应参与者或具体事件不替换 A。局部物种仍通过既有显式
  操作设为研究对象。工具内手动输入 B 不自动建立或替换研究 Species。
- 独立工具无需先选研究物种；打开工具不能因为已有 A 就隐式执行查询或过滤所有结果。
  查询输入与结果必须明确对应实际目标，避免顶部 A 与当前查询 B 混淆。
- 更换研究物种或源修订后，沿用现有依赖结果失效规则；不在本次新增恢复旧研究会话的承诺。
- 直接生成／消耗通道保持一步查询，包含未满足候选主线载体条件的反应。
- 候选路线的三种模式、逐步证据与 Continuous MD Support 的区分保持不变。
- 聚合反应记录不保证存在逐时事件证据。缺事件证据时保留可用反应结果，说明不能展开事件
  的原因；不能把缺能力表现为“零次事件”。
- unresolved 事件保留可用元数据与统计，但不能冒充可定位分子并打开轨迹的 matched 事件。
- 现有多来源对比不切换 Current Dataset；逐来源精确身份、时间换算与条件／Replicate
  确认规则保留。数据导入和 preparation 生命周期不因布局改造改变。
- 各操作分别判断能力；进入物种／演化等容器不要求所有子分析同时就绪。只具丰度证据时
  可看相应排行与趋势，缺反应统计、事件或坐标只影响依赖这些证据的操作。

## 4. 状态和返回的最小要求

先沿用已有 store 与交接信息，仅补完成本次操作链必要的状态。不引入第二套 Current Dataset。
每次下钻记录一个有限的返回位置，可用轻量栈实现；无需开发通用路由／历史框架。

| 状态 | 归属与要求 |
| --- | --- |
| 当前数据与研究 Species | 继续绑定 Dataset Identity 和源修订；选择数据候选不是切换 |
| 对象详情与显示阶段 | 对象种类、精确身份、来源；检索、详情、当前分析；显示切换不提交新查询 |
| 工具输入与结果 | 记录实际输入、提交请求身份和来源；从详情带入与独立填写使用同一分析能力 |
| 当前事件 | 稳定 event_id 加来源、修订；新事件替换旧事件时清理旧轨迹、几何、追踪结果 |
| 返回位置 | 来源入口、有效查询引用、选中物种／路线／步骤／反应、事件页、分布筛选与必要显示位置 |

返回优先恢复同一来源与修订下的现有结果和选择，不重新执行候选发现或其他分析。
返回不等于跳过证据检查：事件重新打开／书签恢复时，按现有契约核验身份与修订，从已发布
索引读取所需事件。刷新不自动读取轨迹，不在浏览器持久化完整轨迹或大型结果。

如果数据或修订已经变化，旧返回位置不能恢复成当前有效证据；显示原因并回到可操作的
入口。数据切换失败或取消保留原状态。任何迟到查询、事件读取、几何或追踪响应都不能
覆盖已更换的数据、请求或选中事件。

“返回原位置”验收重点是：同一条路线、同一步、同一事件页和所选事件仍在；从演化／反应
到物种详情后返回时，原图表选择、筛选与反应结果仍在。图视口和列表滚动尽可能沿用现有
视图状态。不要只跳回入口首页然后重新搜索。返回链仅保存轻量位置和结果引用，设定容量；
失效的来源修订不能通过返回重新激活，刷新时仅按已有可验证的书签规则恢复。

## 6. 分阶段实施

### 阶段 0：确认起点并同步目标文档

1. 读根目录和工作区域 AGENTS.md、CONTEXT.md、设计基准相关章节、有效 ADR；使用
   reacnet-dash-workflows 技能。改动科学结果或索引时才额外启用对应技能。
2. 检查 `git status --short`、已有 diff 和未跟踪文件。本次讨论之前已经存在应用、测试、
   基准和 ADR 修改，属于实施起点；不要 reset、覆盖、忽略或重新生成这些工作。
3. 沿一次“物种 → 路线 → 事件 → 核查 → 返回”的现有链路记录状态读写，选取现有小型
   fixture 验证起点；同时核对反应、演化、事件各自独立打开所需的能力。已有失败单独记录，
   不为绿色测试静默放宽科学要求。区分 §3 的本期能力与后续扩展。
4. 在实施任务中新增 ADR 并同步设计基准，替代范围见第 7 节。核对最新 ADR 编号后再命名。

完成标准：实现者明确本次 UI 目标、保留规则和改动基线；不再把本方案展开为新的产品访谈。

### 阶段 1：建立对象入口并做通物种内分析

1. 创建物种页的检索、详情和分析结果显示阶段，复用现有结构选择、身份、统计和按钮。
2. 将候选路线、直接通道、丰度结果接入对象主内容区；使用当前详情对象作为明确输入，
   保留查询参数调整和三种候选模式。不要从全局研究物种猜测每一次局部查询的目标。
3. 去掉重复概览、重复物种横幅和常驻任务排；显示结果时给出实际目标与返回操作。
4. 增加“RNG 数据／物种／反应／演化／事件”平级入口，映射已有分析能力，避免过渡时丢
   入口。默认布局与 compact 布局、数据页分析入口和 JS 高亮一起更新。
5. 查询能力接收来源、目标与参数；入口、返回位置和显示模式由展示层传递。必要时抽取共用
   物种选择和详情布局，但不要求先做一个覆盖所有页面的通用框架。

完成标准：A 的三类分析都能直接从详情打开；查看 B 时操作确实针对 B；返回搜索结果保持
输入与结果。页面不过度堆叠，身份不重复，打开反应／演化／事件不要求先研究一个物种。

### 阶段 2：做通“结果 → 事件详情 → 全宽核查 → 返回”

1. 从现有事件／轨迹布局提取共用详情入口，复用参与者、键图、轨迹、导出、DFT 与追踪功能。
2. 接通路线步骤、直接通道、独立反应检索和独立事件检索的事件选择；使用稳定身份与来源，
   由已发布索引重读所选事件，不能拿显示行号或前端缓存内容替代证据身份。
3. 在原结果附近显示事件列表和详情；需要时展开为全宽核查。选中另一事件清理前一事件的
   轨迹与几何等派生视图，并拒绝前一事件的迟到响应。
4. 复用已有候选返回信息并补齐通道／反应／事件查询的返回位置。关闭详情和关闭全宽模式
   各恢复正确的上一层，Escape 与焦点行为保持一致。全宽核查仍高亮其发起入口，不把
   所有详情下钻都改成跳到“事件”页。

完成标准：从非首个支持事件进入核查后，仍能回到原路线步骤和事件页；直接通道和独立
反应检索也能完成同样流程。缺坐标时已有事件／分子证据可见，坐标相关操作明确不可用。

### 阶段 3：完成反应、演化、事件的独立职责与多入口交接

1. 反应页接入独立反应式查询、反应详情／事件列表和现有多来源对比；事件页接入已有独立
   事件查询。同一反应／事件对象的详情与物种起点复用，不复制计算或统计逻辑。
2. 演化页接入单／多物种趋势、元素分布和多来源物种比较；利用丰度索引摘要提供本期累计
   采样丰度排行，明确指标和范围，有界获取数据与结构预览，支持精确物种下钻。
3. 从反应参与者、排行行、元素分布中的精确结构打开 B 的物种详情；保留原反应或分布的
   条件、选择、结果和返回位置，不要求重搜 B。尚未确定精确身份时先提供结构选择。
4. 使用有界会话返回链连接这些下钻。访问 B 不替换研究 A，B 的分析不误用 A；不同来源
   按 §2.5 显式交接。返回不隐式切换来源或重新激活已经失效的研究结果。
5. 保留趋势中的多来源选择、返回单来源状态和无 Current Dataset 时的独立比较；保留
   反应条件／Replicate 元数据确认。新增来源不自动得到可比的物种、事件或统计组。
6. 在物种页保留“直接探索路线”，演化页可直接填写多个物种；无需预先建立研究锚点。
   §3 的原子筛选与未定义时段统计仅记录为后续能力项，不用部分结果模拟完整查询。

完成标准：用户能从反应、演化、事件直接开始；演化 → B → 路线 → 事件 → 返回演化、
反应 → 参与物种 B → 趋势 → 返回反应两条交接链均可用。

### 阶段 4：迁移旧会话并完成兼容收尾

1. 迁移旧 `page-store`、任务值和事件书签；必要时为展示状态增加版本，区分旧 `reactions`
   代表“物种研究”与新 `reactions` 代表“反应”。不能只按同名 ID 错误恢复页面。
2. 旧研究概览转为物种详情或检索；旧候选任务／`candidate-paths` 转为物种页路线入口；
   有效直接通道按其已保存的目标与来处恢复，独立反应式查询归入反应页。没有完整上下文
   时落到可操作入口，不自动提交查询。
3. `reaction-compare` 转为反应的对比模式；`element-distribution` 转为演化的分布视图；
   `batch-compare` 转为演化的丰度比较模式；已有 `evolution` 单来源输入与结果保留。
4. `trajectory` 有有效事件上下文时恢复共用详情；无法通过来源／修订校验时给出原因并
   返回有效来处或事件查询入口，不显示旧轨迹。`pathway`、`species-fate` 安全迁移到
   相关入口，不重启已退役分析。
5. 检查能力提示、准备完成后的交接、数据切换后的目标位置，以及旧 JS 映射，不留下
   按钮只改变隐藏视图、旧导航闪烁或数据绑定错位。

完成标准：同一分析没有复制两套控件；旧会话可恢复或得到清楚提示；来源与请求失效规则
在所有入口一致生效。随后完成第 8 节的完整验收。

### 阶段 5：完整验收与交付

完成第 8 节的场景和测试。交付最终行为、文档变动、实际测试结果与未完成的浏览器／真实
