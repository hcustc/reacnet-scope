# ReacNet Scope 使用逻辑

## 设计原则

ReacNet Scope 采用工具箱结构：

- 通用能力保持小而独立，可以单独使用。
- 自动化能力单独分组，不与基础检索混在一起。
- 左侧栏始终展开全部功能入口；分组只表达类别，不使用下拉菜单。
- 页面内部只保留标题、数据状态和直接操作区域，不再用卡片包裹完整功能。
- 页面之间只传递必要的物种、反应或事件上下文，不复制分析算法。

## 侧栏导航

所有入口均直接可见，组间只用分隔关系，不设置需要再次展开的菜单。

| 分组 | 功能 |
| --- | --- |
| 通用工具 | 物种检索、反应式检索、时间演化、反应事件、轨迹查看 |
| 自动分析 | 中间体筛选、候选路径、组成演化 |
| 数据工作区 | 管理数据、批量对比 |

默认进入“物种检索”，不再设置分析首页或强制流程。“管理数据”和“批量对比”
作为独立页面放在侧栏的数据工作区中。

## 功能边界

| 功能 | 主要职责 |
| --- | --- |
| 物种检索 | 按分子式、SMILES 或质量定位物种 |
| 反应式检索 | 按反应物和产物组合查找反应 |
| 时间演化 | 查看一个或多个物种的丰度曲线 |
| 反应事件 | 检索并选择具体 RNG 事件 |
| 轨迹查看 | 独立查看局部反应轨迹、关键帧并导出复核文件 |
| 中间体筛选 | 按丰度、寿命和通量自动筛选候选 |
| 候选路径 | 从指定物种自动扩展有界路径 |
| 组成演化 | 按 C/O/Cl 条件筛选并查看组成变化 |
| 管理数据 | 选择当前数据集、检查文件就绪状态并准备索引与缓存 |
| 批量对比 | 从数据管理中选择多组模拟结果进行比较 |

### 批量对比

“批量对比”支持两类可组合的数据来源：

- 当前数据集和浏览器中最近成功加载的数据集；每个数据集作为一个条件组。
- 多条件根目录扫描；扫描当前目录及最多四层子目录中的 `.reactionabcd`。

目录名中的 `T`、`O2`、`P` 和 `rep`/`run`/`seed` 会用于自动分组。例如
`T300K_O2-0.1_rep1` 与 `T300K_O2-0.1_rep2` 属于同一条件组；没有物理条件
字段的 `case_rep1` 与 `case_rep2` 也会按 `case` 分组。扫描路径仍受
`REACNET_SCOPE_ALLOWED_ROOTS` 限制。

比较以有方向、保留化学计量数的精确 SMILES 反应键为准，不用分子式替代
结构匹配。主表按条件组显示检出率、平均 TP、TP 标准差和平均净 TP；选中
反应后可查看每个重复实验、误差条和 Student-t 95% 置信区间。最小检出率按
所有选中重复实验计算，`Top N` 在检出率过滤后限制结果数。任一选中数据源
缺失、重复或解析失败时，本次对比整体停止并指出具体条件，避免输出不完整
结果。CSV 使用与页面一致的中文列名。

## 跨工具衔接

工具保持独立，但允许以下快捷交接：

- 物种 → 反应式检索中的生成/消耗通道、时间演化、候选路径。
- 反应 → 候选路径、反应事件。
- 中间体候选 → 候选路径、时间演化。
- 候选路径反应 → 反应事件。
- 反应事件 → 轨迹查看。

这些交接只负责填充目标和切换页面，分析逻辑仍由目标工具统一执行。

## 去重原则

- 页面名称和导航分组只在 `navigation.py` 定义。
- 通用分析逻辑集中在 `services.py` 和核心模块。
- 自动分析调用通用服务，不重新实现物种、反应或事件检索。
- 物种核查统一沿“物种 → 生成/消耗通道 → 通道事件”展开，不再维护独立核验页面。
- “高级”仅用于少用参数，不再作为完整功能入口。

## 当前范围与未来候选

当前产品链路是“反应式检索 → 有界候选路径 → RNG 事件 → 局部轨迹与事件包”。
事件包属于当前能力：Dash 和 `reacnet-scope export-event` 导出
`event.json`、`trajectory.lammpstrj`、可选 `trajectory.extxyz`、
`bonds.csv` 与 `README.txt`。

机理网络尚未形成可执行方案，不在当前导航、版本承诺或发布验收中；旧方案实现
和专项实施计划已经删除。“机理网络”只保留为未来候选功能名称，不预设数据
模型、界面或导出格式；若重新启动，应按届时确认的需求重新立项和设计。
