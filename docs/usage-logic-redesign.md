# Dash 使用逻辑

当前信息架构以用户任务和证据层级分组：

| 分组 | 工具 |
| --- | --- |
| 检索与趋势 | 物种检索、反应式检索、时间演化、元素分布演化 |
| 事件证据 | 反应事件、轨迹查看、路径验证 |
| 数据工作区 | 管理数据、批量对比 |

核心链路是“物种/反应式检索 → 反应事件 → 局部轨迹与事件包”。单步 Direct
Reaction Channel 只展示焦点物种的直接生成或消耗通道。

“路径验证”是独立证据任务。用户按顺序提供 2–8 个完整 Reaction Type，软件用具体
事件的严格时间先后、相同分子实例和连续原子 ID 判断整链是否有证据。结果固定为
“有证据 / 未观察到 / 证据不足”。它不根据起点或终点自动扩展，不补全步骤，不评分
排名，也不生成 Top-N 合并网络。

跨工具交接只传递精确 SMILES、规范化 Reaction Type 或稳定事件 ID。数据集选择、
能力状态和派生索引准备集中在“管理数据”；切换 Current Dataset 会清空旧数据集的
分析结果，但保留可安全复用的查询文本。

## Dash 界面优化规则

- 顶部导航的“当前数据集”始终可见；顶部操作中的数据集按钮会按状态显示为
  “选择数据集”或“更换数据集”。
- 数据集浏览器明确区分“当前数据集”和“候选数据集”；浏览、筛选和候选检查都
  不会改变 Current Dataset，只有“加载并使用”会触发一次原子验证和切换。
- 加载按钮旁始终说明下一步和影响：候选未选、验证中、失败、已是当前数据集
  以及正常切换各有独立文案，不使用仅有禁用态的解释。
- 查询类表格在新结果返回时清空旧选中行和活动单元格，避免 Dash 复用上一轮
  `selected_rows` 造成错误交接；切换 Current Dataset 同时清空反应通道、轨迹、
  事件路径和批量对比中的旧选择。
- 导航使用应用内离线 SVG 图标并保留可见文字；当前页面提供 `aria-current`，
  数据集状态和反馈区域提供 `role="status"` / `role="alert"` 与适当的
  `aria-live` 播报。
