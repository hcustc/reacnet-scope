# Dash 工作台 UI 开发约定

五个平级入口“RNG 数据／物种／反应／演化／事件”共用紧凑桌面布局；各入口在对象详情或观察结果附近显示相关操作，不显示旧常驻任务排。事件从路线、反应或独立查询进入同一详情抽屉，再按需展开全宽核查。领域身份、能力、索引及导出契约仍以 [软件设计基准](software-design-baseline.md) 为准；展示决策见 [ADR-0029](adr/0029-open-analysis-from-species-reactions-evolution-and-events.md)。

## 组件与依赖

- `scripts/webapp_dash/ui_components.py` 提供 Community AG Grid、列定义适配、稳定行身份、反馈和结果工具栏。
- `scripts/webapp_dash/ui_state.py` 管理表单反馈、Enter 提交和局部视图状态。科学计算仍调用核心服务。
- `assets/workbench.css` 统一布局尺寸、字体、间距、控件、表格和响应式详情；`app.css` 保留图、轨迹、数据选择器等功能样式。新通用样式集中写入前者，避免在后者追加同类覆盖。
- `assets/grid_components.js` 提供行身份和结构预览。预览使用本应用 SVG 接口，按需加载，不执行数据中的 HTML。
- `assets/workbench.js` 支持 Escape 关闭详情或返回上一阶段；打开模态框时由 Bootstrap 接管 Escape。
- 使用 Dash AG Grid Community，不启用 Enterprise 模块。保留 Dash / dash-bootstrap-components、Plotly、Cytoscape 和 3Dmol，不增加 Node 构建链。
- `assets/bootstrap-local.css` 为 Bootstrap **5.3.8** 的完整本地 CSS，并保留同目录 MIT 许可证。通过 external_stylesheets 的本地地址先加载，随后加载应用 CSS；不依赖 CDN 或 Bootstrap JavaScript。

更新 Bootstrap 时从官方发行包取得 CSS，核对许可证和完整性，并重验 Modal、Dropdown、Offcanvas、Collapse、焦点和移动布局；不要在 vendor 文件中混入业务覆盖样式。

## 表格约定

所有结果表使用 `result_grid()`。原有服务列元数据通过 `columns()` 转换；服务与 CSV schema 不因为 UI 库迁移而改变。

| 旧 DataTable 属性 | 当前接口 |
| --- | --- |
| `data` / `columns` | `rowData` / `columnDefs` |
| `selected_rows` / `selected_row_ids` | `selectedRows`，内容为原始数据行对象 |
| `active_cell` | `cellClicked`，使用 `rowId` |
| `page_current` | `paginationGoTo` |
| `hidden_columns` | `columnState` 中的 `hide` |
| `tooltip_data` | `<grid-id>-previews` Store，由共享回调按行身份关联 |
| `page_size` | `<grid-id>-page-size` Store |
| `data_timestamp` | 编辑回调使用 `cellValueChanged` |

不能将 DOM 顺序、可见行号或排序后的下标作为 Species、Reaction、Occurrence 或候选路径身份。服务已有 `id` 时沿用；物种使用精确 SMILES，质量聚合行使用分子式。选择对象需要在当前结果中重新解析，不能直接信任旧选择中的数值。

浏览器端排序只作用于已加载结果。使用服务端事件分页的表格关闭本页排序，继续使用原有翻页服务与总数说明，避免把局部排序呈现为全体排序。列宽可调整；默认不启用第二套浏览器筛选，避免与科学查询表单混淆。

## 查询与状态

- 物种和反应查询记录已提交条件；改动输入时保留上次结果并显示“条件已修改”。用户点击查询或按 Enter 才重新计算。
- 事件查询的反应式、结果上限及轨迹窗口输入支持 Enter 提交，复用同一查询按钮与运行锁；反应时间分布的窗口输入也支持 Enter 应用。轨迹窗口按需展开，折叠标题保留当前前后帧数。反应的 Top 占比参数仅在勾选计算时展示，收起不丢弃已选值。
- 查询运行时禁用重复提交。初始等待、运行、有效空结果、缺少能力和失败分别反馈；错误不包装成成功空结果。
- 浏览器标签页保留应用名称；初始化和后台能力刷新不反复改写标题。运行进度与失败原因仍在相应查询或准备任务旁展示。
- 自动类型识别为质量或手动选择质量时显示容差；零值有效，负数和非有限数值拒绝提交到服务。
- `guarded_query()` 将服务器计算和浏览器提交分开。响应携带提交序号及 dataset_id/source_revision/artifacts；提交时任一不匹配即丢弃，防止迟到结果覆盖当前上下文。
- RNG 数据切换继续使用原有两阶段事务；检查候选不更改当前RNG 数据。表格初始化的空选择不能清空已恢复的当前RNG 数据。
- 多来源对比的上下文仍由其来源集合决定；后台候选分析和 preparation 继续使用原有任务状态、取消和修订检查。

## 布局与键盘

桌面顶栏 56px、侧栏 192px、主要控件 36px、表格行 36px、主要间距 12px。页面不设通用“使用帮助”栏；
必要说明放在相关控件附近。导出与结果操作位于结果区。物种检索中选中精确结构即打开该物种详情；详情直接提供生成路线、后续转化、相关反应与丰度趋势，结果保留其精确物种、来源和修订。反应式、丰度排行、元素分布与事件均可独立开始；从它们打开精确物种详情时，该详情物种就是其操作目标，不出现“设为研究物种”操作。

两种导航布局共用顶部当前数据菜单：点击数据名称即可选择已导入来源，明确点击“切换数据”后走原有两阶段验证。只选择选项不改变当前数据；失败在菜单内显示原因，成功关闭菜单并保留发起的分析入口。导入新文件夹使用“添加数据”，准备、清理与完整列表仍由 RNG 数据页管理。

各页的阅读位置只在当前浏览器页面内有界保存，支持桌面内容区与窄屏整页滚动；往返入口恢复位置，不重新提交分析。数据身份、源修订或工件映射改变时清空位置。导航观察器只监听页面本身的可见性类，不监听表格单元格、图节点等内部更新。Tab 可进入“跳到分析内容”链接；数据菜单支持 Escape 关闭并返回菜单焦点，外部点击或焦点移出也会关闭。

演化页共用一个逐帧丰度曲线区。精确物种列表的累计采样丰度用于排序，选行只更新本页曲线；切换为元素原子数分组后，曲线显示组总量，点击时间点列出组内精确物种，选中成员显示该成员和组内其余物种。进入物种页是单独的明确操作，返回后保留演化页的选择。高级元素筛选沿用原有独立分析入口。

候选路径的查询区只常驻精确结构选择和主要搜索参数，放大结构与高级选项按需展开；
往返处理的模式、窗口和依据在折叠标题中可见。有路线时收起查询条件，默认显示当前与勾选路线，
可切换“返回路线总览”。“路线阅读”保持结构可读的缩放，长路线通过平移、步骤选择和“定位当前步骤”阅读；
“适应全部”是显式操作。总览按画布比例排列，远距离仅显示节点轮廓，放大后显示结构与标签。
两种视图都保留完整参与物和共享反应身份；阅读视图将非主线参与物放在对应反应附近，同一 Species 的局部重复图像
沿用相同精确身份及 S 标签，不表示新增物种或具体分子实例。菱形标注反应类型总次数，步骤面板另列主线转移支持次数。
点击反应菱形或连线后才展开步骤证据：宽屏在图旁显示，较窄窗口移到图下方，收起后将空间还给图。
步骤面板依次展示完整反应与唯一的观测列表，计量重复显式标注；反应物和产物换行排列，不依赖横向滚动读完整反应。
选择观测后点击“查看这次反应”进入共用事件详情，实际 RNG 键图在此核查；未解析事件仍可查看元数据及限制。
不再并列提供实例下拉框、逐实例前后按钮与第二份实际键图。观测翻页、换步骤或换查询清空旧选择，交接按事件 ID 重新读取。
具体分子的追踪从共用详情里的“追踪这个产物/反应物”发起，明确传递参与者；返回保留路线、步骤和观测页。
整条路线的连续历史检查位于路线级，其检查状态在折叠标题中可见。
路线切换与继续探索分组排列，无可用历史或分支页时隐藏对应按钮；JSON/CSV 合并在导出菜单中。
路线表格与比较位于图下方；读图说明与精确标签按需展开。
搜索截断、代表身份限制及连续历史尚需独立检查的提示保留在结果旁。正常就绪不显示准备横幅或入口，
缺证据及降级状态保留原因和准备入口。

物种检索、质量检索的结构列表与物种详情依次占用结果区；详情使用完整结果宽度显示结构图和统计，不在窄侧栏中压缩。进入详情聚焦返回按钮，Escape 或关闭按钮返回前一阶段；再次点击同一行可以重开。事件详情窄屏占可用宽度，全宽模式保留明确返回。窄屏查询条件换行、详情内容纵向排列，表格在自身区域滚动，页面不应横向溢出。

## 验证入口

行为单元测试：`tests/test_workbench_ui.py`；既有 Dash HTTP、身份交接、索引、对比与导出测试继续覆盖服务边界。

浏览器验收：`tests/browser/test_workbench.py`，使用临时 RNG 数据和本机服务器；包含排序后精确选择、结构预览、CSV 下载、Enter/Escape、旧请求/旧RNG 数据/旧修订响应、迟到轨迹与谱系响应、五个入口、研究 A 时查看 B、反应与演化起点、共用事件详情、质量容差零值、首屏结果空间和窄屏。候选步骤的非首条观测、前后键图、指定产物追踪与返回，以及十步路线的总览/阅读/定位在隔离小样例上验收；大型真实网络与复杂轨迹仍需在代表性数据上验收。安装和运行方式见 [验证指南](agents/testing.md)。

小型 fixture 和 Chromium 验收不能代替大型真实数据吞吐、物理单位确认、复杂轨迹渲染或跨平台验收。

## 多文件夹导入与使用

1. 打开左侧“RNG 数据”，点击已导入列表中的“添加数据”；顶部“添加数据”也可打开文件浏览器。在目录列表点“加入”，或点“加入当前文件夹”；也可展开“一次填写多个文件夹路径”，每行填写一个软件运行机器可访问的目录。
2. 核对待导入列表，点击“导入所选文件夹”。成功项保存在当前浏览器；失败项显示原因。每个文件夹保持独立，导入不切换正在分析的数据，也不自动准备索引。
3. 在“RNG 数据”页面的已导入列表中点击“切换到此数据”；验证成功后更新 Current Dataset。失败时原数据保留。
4. 在“演化”的丰度趋势中添加对比来源，或从“反应”打开多来源对比。比较来源选择不改变普通分析使用的当前RNG 数据；所需索引与精确结构仍按来源分别确认。

“已导入的RNG 数据”可以移出引用，不删除原始文件或工作区。列表按浏览器与站点保存，刷新保留，不在不同浏览器之间同步。相关回归见 `tests/test_dataset_library.py` 和浏览器多文件夹用例。

RNG 数据页面上方的“RNG 数据管理”区域显示当前数据状态与全部已导入引用，未加载时共用列表上的“添加数据”入口；索引准备管理仍按能力显示。可逐项切换或移出列表，不提供对比控件或数量门槛。下方分析入口指向物种、反应、演化和事件；从能力提示进入时聚焦相应的准备控件。

导入页没有待导入列表时，“导入当前文件夹”直接提交已打开目录；存在列表时按钮显示数量，仅导入列表中的文件夹。尚未打开目录时给出操作提示，不把空请求报告成文件导入失败。
