# 目标物种、路径步骤与反应实例开发计划

日期：2026-09-21。
状态：已实施；自动化验收完成，浏览器视觉与真实数据人工走查待发布环境补充。
交互依据：[目标物种使用流程方案](target-species-workflow-proposal.md)及本次讨论。
历史：[五工作区收敛计划](development-convergence-plan.md)已完成，保留其原阶段和验收记录。
科学身份、步骤证据、连续性与几何导出继续遵守[设计基准](software-design-baseline.md)
和有效 ADR；本计划不重新定义候选路径或 Reaction Occurrence。

## 1. 本轮完成目标

用户可以直接完成：

> 选择目标物种 → 查找候选路线或直接反应 → 点击图中反应步骤 → 浏览并切换具体实例 →
> 核查前后结构和局部轨迹 → 导出事件证据或该实例的 DFT 初始几何。

路径图是主要探索入口。保留现有“物种结构卡 → 反应菱形 → 物种结构卡”表达；点击菱形
或其两侧连线，打开同一个反应步骤的详情。所说“在边上查看分子变化”，落实为步骤的
实例证据和原子变化详情，不把多个独立实例画成一条已经连续发生的历史。

选中实例后，可进一步追踪其中某个参与分子的此前、后续变化。此功能界面称“分子变化追踪”，
作为实例详情里的可选操作，不要求用户先进入独立工具，也不作为候选路线或 DFT 导出的前置条件。

### 固定边界

- 各步骤允许来自不同具体分子的记录；仍满足既有精确结构、有向计量和事件内原子传递要求。
- 未找到完整连续实例不否定候选路线，不减少其步骤支持计数，不参与默认排名。
- 完整反应式或主线载体不同的步骤不能只因同为 A→B 而合并；共享步骤的计数不按路线重复累加。
- 一个具体实例是一次 Reaction Occurrence。同一区间的多次发生分别保留，区间内部不虚构先后。
- 步骤支持数、反应类型总发生数、未解析数的范围分别说明；不能用当前一页记录冒充总体统计。
- DFT 前后几何来自同一次已匹配事件及其精确帧，不混用不同实例，不新增优化、TS/IRC 或作业调度。
- 原始 RNG 工件只读；在线操作继续消费已发布索引和有界帧，不因展开详情扫描原始大文件。

## 3. 开发顺序

执行顺序：**阶段 0 → 1 → 2 → 3 → 4 → 5**。每阶段均需通过自身检查。
阶段 1–3 完成后，执行对应浏览器与真实案例验收，可交付首个主线版本；阶段 4 的可选追踪
不作为该版本的前置条件。阶段 5 是本轮整体收尾，不把身份和时序测试全部推迟到最后。

| 阶段 | 交付 | 状态 |
| --- | --- | --- |
| 0 | 固定现状、来源和回归基线 | 已完成 |
| 1 | 图中步骤与实例详情整合 | 已完成 |
| 2 | 所选实例到结构查看的交接及返回 | 已完成 |
| 3 | 当前实例的事件包与 DFT 几何导出 | 已完成（复用既有导出契约） |
| 4 | 可选变化追踪与导航整理 | 已完成 |
| 5 | 整条操作链验收、清理与使用说明 | 自动化完成；人工验收待补 |

### 阶段 0：固定可比较的基线

1. 记录当前已有未提交改动与来源，不覆盖或混入其他工作的修改。
2. 固定一个能搜出多条候选路线、至少一个步骤有多个实例的现有案例；记录数据集身份、
   源修订、查询参数、索引能力和实际返回范围。截图中的“20 条路线”不作为所有版本的常量。
3. 核实用于 DFT 验收的案例具备精确前后坐标、元素映射及长度单位；缺失项如实记录。
4. 运行受影响测试取得当前基线；已有失败与本轮回归分开记录。
5. 核对控件、stores、Python/JS 引用及恢复路径，列出可复用的事件书签与导出逻辑。

完成条件：可以重复执行同一个查询与实例选择；已有能力、缺口和未验证项可区分。
本阶段不重处理 RNG、不自动重建全部索引、不开展全仓库重构。

### 阶段 1：让图中的步骤直接承载实例证据

主要修改：`candidate_graph.py`、`candidate_workbench.py` 及必要的局部样式。

1. 保留已有图选择逻辑；菱形和两侧连线进入同一详情。共享步骤优先保持当前路线，
   需要切换路线时显式显示其归属，不因点击共享物种而暗示生成了一条新的返回路线。
2. 图旁详情按“步骤概览 → 反应实例 → 当前实例结构”组织。概览显示完整计量、主线载体、
   支持数与折叠规则；实例页分页查询，原始支持实例仍可查看。
3. 合并重复的实例表与下拉选择行为，以稳定事件身份控制当前实例。提供上一/下一实例，
   到达页边界后按已有分页读取；列表顺序是浏览顺序，不表示同一区间内的反应先后。
4. 切换步骤重置不再适用的实例；切换实例保留路线和步骤。缺证据、未解析、加载失败和
   有效空结果分别呈现，旧步骤的异步响应不能覆盖新步骤。
5. 连续实例检查收进可选分析，使用事实状态，不给路线显示通过/不通过或自动评分。

完成条件：用户点击任一返回路线的步骤，就能在同一上下文中浏览多次具体发生及其原子变化。
测试重点：共享步骤不重复计数；同主线但共同参与者不同的反应不合并；相同时间区间的实例
不合并；实例分页、空结果和查询替代正确。

### 阶段 2：从所选实例进入结构查看，再返回原步骤

主要修改：`candidate_workbench.py`、`callbacks.py`、`app.py`；必要时在现有服务门面补适配。

1. “查看前后结构与轨迹”直接交接所选 `event_id`，复用现有事件核验和书签机制。
   用户无需在事件页重新选一次；若继续复用独立轨迹页，进入后明确显示当前实例。
2. 交接记录来源上下文和返回位置：数据集/源修订、候选查询、路线、步骤、事件分页、
   选中实例与必要图视图。可显示面包屑，但显示序号不是科学身份。
3. 接收端从索引重读所选事件，并核对其仍属于原步骤。参数或源修订变化拒绝旧交接，
   不直接信任前端复制的事件行。
4. 核查面板展示全部反应参与者、精确前后键图与原子对应；有坐标时按需读取局部轨迹。
   无坐标时保留已有分子证据，单独说明坐标查看能力缺失。
5. 返回恢复原路线、步骤、实例和视图，不自动重跑搜索。数据集切换或新查询替代旧查询后，
   旧实例、轨迹及异步结果不能被恢复为当前内容。

完成条件：从图上选中的实例到结构查看，再回到原步骤，始终是同一个事件。
测试重点：选择第二个实例交接时不能回到第一个；快速从实例 A 切到 B 后，A 的迟到轨迹不能
覆盖 B；两个同结构参与分子保持独立；修订变化、失败和返回分支均明确。

### 阶段 3：完成当前实例的证据与 DFT 导出

主要修改：已有 DFT 卡片、事件导出和相关回调；复用 `reacnet_scope` 中的现有几何服务。

1. 从所选实例直接进入“导出事件包 / 导出 DFT 初始几何”，沿用已有参与分子选择和预览。
2. DFT 反应物使用该事件的精确 before 帧，产物使用精确 after 帧；保留完整分子、原子映射
   和多分子相对位置，按既有规则处理周期边界。源坐标、元素、单位和完整性要求继续生效。
3. 导出及预览绑定事件、数据集修订与几何参数；实例或参数改变立即使旧预览失效，下载前
   再核对当前身份。不同实例的前后结构不得被标为同一次发生。
4. 沿用既有事件包、XYZ 几何包及 manifest，明确这是未优化初始结构。基本几何导出与
   可选 QC 交接沿用各自已有要求，不把扩展检查变成新的默认科学结论。
5. 支持逐实例选择和导出，以便人工比较不同构象/取向；首轮不新增批量筛选、环境裁切或
   特定量化软件作业生成。

完成条件：从图中一个步骤选任一满足几何条件的实例，可以导出与它严格对应的几何及来源记录。
测试重点：切换实例后旧下载失效；缺精确帧不能取最近帧替代；未解析事件不能导出几何；
PBC、完整分子、元素和 Å 条件继续通过已有回归。检查真实导出内容，不只检查按钮是否可点。

**阶段 1–3 的首个交付点：图 → 步骤 → 多实例 → 结构 → 导出全程走通，并通过对应验收。**

### 阶段 4：把可选变化追踪放入实例详情，整理整体入口

主要修改：`lineage_explorer.py`、`candidate_workbench.py`、`callbacks.py`、`navigation.py`、`app.py`。

1. 在当前反应实例详情提供“追踪这个分子的变化”，让用户选择反应物或产物中的具体参与分子。
   同 Species 的多个参与者分别显示，不用 Species 或下拉序号代替实例身份。
2. 将“分子谱系”等界面主文案调整为“分子变化追踪”，保留既有领域对象与导出含义。
   用户按需展开此前/后续变化，查看结束原因，再返回原反应实例。
3. 变化追踪图中的分裂、合并、重复出现、锚点丢失/返回继续按现有严格规则表达。
   图中相邻候选步骤不自动连接成某个实例的连续历史，缺失记录不跨越。
4. 根实例、锚点与所选事件明确显示；切换实例时清空或显式关闭旧实例的追踪内容，避免
   B 的结构旁仍显示 A 的历史。基本图不以坐标为前提，元素锚点映射等能力分别检查。
5. 保留五工作区归属，按任务理顺入口。候选任务继续位于“反应与事件”；原“轨迹与谱系”
   展示名改为“结构与轨迹”，不新增第六个工作区。趋势和对比保持辅助流程。
6. 同步使用说明及相应产品范围描述：候选分析是本轮研究主线，连续实例是可选证据。
   处理设计基准第 3–4、10 节与 ADR-0018 中原有入口优先级表述；如替代已接受的产品决策，
   记录清楚替代范围，科学连续性规则保持不变。不要仅靠更近的计划日期覆盖有效 ADR。

完成条件：用户从边的实例详情进入追踪，无需重新找分子；未找到连续历史不妨碍该步骤的核查
与几何导出；普通主线不要求使用追踪。完成候选/分子图的语义区分及返回验收。

### 阶段 5：整条流程验收与收尾

1. 清理被整合后重复的详情、实例选择器及无引用回调；先检查 Python、JS 和测试引用，
   不删除仍被直接通道、事件检索或公共 API 使用的组件与服务。
2. 完成阶段测试矩阵、全量回归、浏览器操作和固定真实案例；记录环境、来源、参数、
   实际结果与未验收项。缺浏览器或真实数据时如实保留缺口。
3. 检查大/窄屏详情、长反应式、多实例分页、无坐标、索引未准备、查询截断和源修订变化。
4. 更新当前使用说明、功能状态和交付记录；提案中已落地与尚未实现的部分分别标明。

完成条件：本轮范围内各动作可复核，五工作区及直接单步入口没有退化，未实施功能没有伪装成
可用入口。原始 RNG 数据不因开发或验收被修改。

## 4. 状态与身份规则贯穿各阶段

| 变化 | 必须处理的旧状态 |
| --- | --- |
| 点击另一步骤 | 清除不属于新步骤的实例选择，拒绝旧步骤返回的分页或结构结果 |
| 在同一步骤选择另一实例 | 清除旧轨迹/几何预览及其下载资格；保持路线、步骤与返回位置 |
| 新搜索替代旧搜索 | 旧图选择、实例请求和返回书签按查询身份失效 |
| 数据集或源修订变化 | 旧来源的结果、几何、实例和追踪不提交到新上下文 |
| 进入或退出实例核查 | 保留有效研究对象及来源；返回不自动重新运行候选搜索 |

请求至少核对所属数据集/修订、查询或步骤上下文与所选事件；只有数据集相同不足以接受
迟到响应。恢复时从稳定引用重新核验，不能保存整套旧坐标作为可长期信任的结果。
Preparation Task 始终属于原数据集及修订，不随页面选择或分析实例切换而改属。

浏览器至少走通“搜索 → 点击共享步骤 → 选择非首个实例 → 结构 → 导出 → 返回 → 换实例”
和“同一步骤快速切换/查询替代 → 旧响应不覆盖新选择”。

真实数据验收记录具体来源和事件身份，不把小 fixture 通过等同于真实规模或跨平台完成。
声明大规模交互性能前，至少在两个数据规模记录实例分页及局部帧读取范围和耗时；发现全量
读取时先修正边界，不用增加预算掩盖问题。macOS/Windows 仍需独立平台验收。

## 6. 首批实施范围与交付记录

2026-09-22 已完成阶段 0–4 及阶段 5 的自动化部分：

- 候选页按“步骤概览 → 支持实例 → 当前实例结构”重组。实例选择由稳定 `event_id` 控制，
  上一/下一实例可跨 25 条一页的证据分页；页面明确说明 Transition 区间内部不推断先后。
- “查看前后结构与轨迹”与“追踪参与分子的变化”均交接当前选中实例。回调从发布索引重读
  对应步骤页，不信任浏览器中的旧事件行；交接会清除旧轨迹、DFT 和变化追踪结果。
- 结构工作区显示当前实例、来源步骤和证据状态；有轨迹时可显式加载局部帧，无轨迹时保留
  分子证据并说明限制。候选入口返回候选路线，原事件入口仍返回事件列表。
- “分子变化追踪”置于可选折叠面板；追踪按钮会直接展开该面板。工作区展示名改为“结构与
  轨迹”，页面入口只要求事件能力，坐标和 segment 能力由各操作独立检查。
- 既有事件包和 DFT Initial Geometry 服务未改变科学契约。DFT 卡仍只在 viewer 与所选
  `event_id` 一致时出现，并继续要求 matched occurrence、精确前后帧、完整分子、元素和 Å。
- [ADR-0020](adr/0020-center-dash-on-candidate-step-occurrences.md)记录新的产品主线，只替代
