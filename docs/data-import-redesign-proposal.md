# 数据导入改进提案：以 RNG 文件集合组织数据集

状态：用户已确认设计方向，文件集合导入已接入正式 Dash。本文保留目标方案与原始问题记录；当前实现与兼容边界见 [ADR-0021](adr/0021-import-explicit-rng-file-collections.md)。
日期：2026-09-22。
依据：当前工作区代码及有效设计基准，包含已有未提交改动。
用户优先目标：减少操作，选好数据后即可开始分析。
已确认方向：统一添加多份 RNG 文件；文件夹仅用于批量选取，不限制数据集的文件位置。
界面围绕文件归属和数据集组织，不设置“目录导入 / 文件导入”两种产品模式。

## 1. 推荐决策

将普通入口改为 **“添加 RNG 文件 → 自动识别与组织数据集 → 开始分析”**。

导入输入是显式的文件集合，支持一次多选、跨目录追加和后续补充。文件夹选择只负责
把受支持文件加入该集合；系统不以目录边界、共同父目录或固定命名规则限定数据集。

界面分别回答“当前在分析什么”“这次添加了哪些文件”“这些文件属于哪些数据集”。
用户不需要先选择导入模式，也不需要先整理研究目录。

用户添加所需文件并点击一次“开始分析”，系统负责识别工件、验证来源、复用索引、
安排后台准备和恢复待执行查询。默认进入物种检索；从某个分析页面发起时回到该页面。
数据集概览、来源详情和手动索引维护仍可访问，但不再是日常分析的必经步骤。

“直接进入分析”不等于大型未索引数据可以立即产生结果。首次处理仍需要时间，但用户
不再需要判断该构建什么索引、跳转到哪里构建、完成后再返回并重复提交。
准备中的能力显示明确等待状态；已有能力照常使用。

这项设计重新考虑原来的交互和组织方式，同时保留科学证据约束：RNG 原始工件只读、
来源不混用、单位不猜测、在线查询不偷偷扫描大型文件、未完成索引不可见。

## 2. 改造前的阻力及证据

| 改造前行为 | 对用户的影响 | 依据 |
| --- | --- | --- |
| 主入口是文件夹路径 → 检查 → 确认使用 → 数据集概览 | 选择数据之后仍有独立确认和页面跳转 | `scripts/webapp_dash/app.py` 的数据选择/检查视图；`callbacks.py::_commit_dataset_switch` |
| 加载不启动准备，缺能力提示去数据管理显式建索引 | 用户需要理解事件、组成、轨迹索引及依赖 | 设计基准 §9；`capabilities.py::_reason_for_state` |
| 文件夹选择入口遇到多组数据直接拒绝，要求拆分文件夹 | 用户必须为软件整理已有研究目录 | `workspace_services.py::resolve_dataset_folder_candidate`；`callbacks.py::_select_dataset_folder_response` |
| 按公共文件名前缀发现数据，准备模块也有自身的发现规则 | 同一数据集的组织知识散落，目录外文件关联困难 | `datasets.py::discover_dataset_candidates`；`prepare.py::discover_dataset` |
| 轨迹关联、时间换算和元素映射已经可以保存，但入口分散 | 缺失信息容易到后续步骤才暴露；恢复动作不统一 | `trajectory.py` 的设置读写及 Dash 反应/轨迹控件 |

已有实现的事务化切换、独立能力状态、后台任务、检查点、原子发布和 Workspace
可以继续使用。改进重点是由系统承担流程协调，而非推倒这些基础设施。

**改造前差异：**原设计基准 §8.2 和 README 描述了多候选选择，但原主文件夹选择入口
拒绝多候选。提案以实际代码说明当前阻力，不把该实现反向认定为产品契约。

## 3. 用户流程

### 3.1 一个普通入口：添加 RNG 数据

主入口支持一次多选受支持文件，也可跨目录多次追加。选择文件夹是同一入口的批量
选取快捷操作：列出发现的文件，再交给同一个识别流程，不创建“目录导入”模式。
粘贴多条文件路径可以作为高级快捷方式。最近使用的数据集仍可直接打开。

普通流程在一屏内完成：选取文件 → 自动识别角色与归属 → 点击“开始分析”。
文件角色包括物种丰度、聚合反应、Timed Evidence Source、分子证据及坐标轨迹；
自动归组必须有相应来源依据，名称和位置只能提供建议。

只有一组无歧义数据时自动选中；包含多次运行时展示独立数据集，不混合事件。
用户选择本次分析的一组；其他草稿组保留在本次添加面板内，不自动变成 Current Dataset。
是否批量登记全部组是后续管理能力，不作为单数据集分析的前置步骤。

新增文件就地显示角色、归属和缺项。支持移除误选文件、修正待确认归属，以及后续向
已有数据集补充来源。移除表示撤销本次选择，不删除原始文件。新增、移除或改组后，
原预览及待提交请求随文件集合版本失效，重新计算能力与相关索引依赖。

文件夹枚举范围明确显示，允许包含子目录；大型枚举后台执行、可取消，截断必须可见。
不要求“一个文件夹一组数据”，也不要求不同角色的文件位于同一层或同一路径。

来源位置属于运行 ReacNet Scope 的环境：本机部署选本机文件，服务器部署通过服务端
选择器多选已有文件。浏览器本机文件上传是独立传输能力，不因支持多文件选择就隐式引入。
添加现有工件默认保存引用，不复制数百 GB 轨迹。

### 3.2 打开后的落点

| 发起位置与数据条件 | 落点与行为 |
| --- | --- |
| 普通添加数据，存在 `.species` | 进入物种检索，自动准备所需丰度索引；可先输入目标 |
| 从反应或其他分析页面更换数据 | 返回原任务，保留可安全复用的查询文本，清空旧结果与对象选择 |
| 已有匹配的已发布索引 | 直接使用，不再次准备，不经过概览确认 |
| 仅有聚合反应证据，没有丰度来源 | 进入聚合反应检索并说明证据范围，不把它当成丰度目录 |
| 仅有 timed evidence，没有上述来源 | 进入事件入口，自动准备事件检索；不臆造丰度来源 |
| 所选目标确实缺源 | 在目标页面说明缺少什么，并提供已有能力入口；不让用户反复重建 |

同一数据集内，用户提交的查询如果只缺准备工作，系统保存一次待执行请求。依赖发布后
自动执行，无需再次点击查询。打开新数据集不自动重跑旧数据集的查询；必须是本次打开后
用户明确提交的请求，才能等待并恢复。

### 3.3 页面上显示用户关心的状态

示意文案：

```text
当前数据：2500 K / run 03
目标物种：[ 输入分子式、精确结构或质量 ]  [查询]

正在准备物种检索数据……                  [取消]
你的查询已保存，准备完成后自动执行。
反应检索可用；轨迹将在首次查看时准备。
                                      [查看数据详情]
```

普通界面使用“正在准备物种检索”“轨迹尚未关联”等说明，不让用户先选择 index kind。
可展开详情查看源文件、Workspace、阶段进度、资源占用和等价 CLI 命令。
没有可靠总量或吞吐估计时显示阶段与已处理量，不显示虚构百分比或预计完成时间。

### 3.4 UI 层级：分析上下文、选择器、维护详情

当前混乱有具体的布局原因：数据概览同时容纳当前数据、源文件、能力入口和索引维护；
选择器再嵌入路径输入、按需展开的目录浏览、最近记录和独立检查视图。主目录浏览列表只
呈现子目录，因此用户无法通过看见实际 RNG 文件来确认数据位置。这里需要重组信息，
而不是只换颜色、圆角或按钮文案。

建议在保留现有五个工作区职责的前提下，调整视觉层级：

| 位置 | 只承担的主要职责 | 不在此重复呈现 |
| --- | --- | --- |
| 应用顶部 | 当前数据集名称、打开/更换入口 | 大段来源路径、全部能力状态、索引按钮 |
| 左侧导航 | 四个分析工作区；数据集管理在辅助区域 | 每个分析功能的重复宣传卡片 |
| 主工作区 | 当前分析问题、输入与结果 | 完整导入向导和索引管理面板 |
| 添加 RNG 数据面板 | 已选文件、归属、数据集预览、一次提交 | Workspace 清理、重建命令、全量任务历史 |
| 数据详情/数据集工作区 | 来源关联、缺失信息、准备任务和高级维护 | 再复制一遍分析工具导航 |

这属于五工作区的呈现方式调整，不新增第六个一级入口，也不借导入任务改写所有科学
分析页面。首次无数据时显示“添加 RNG 数据”的清晰起点，不铺满不可用图表和告警。
已经打开数据后，点击顶部数据名称可进入同一个选择器，取消则回到原分析上下文。

### 3.5 文件集合与数据集预览共用一屏

桌面优先采用左右分区；文件浏览器只在添加文件时出现，不占据主界面：

```text
添加 RNG 数据
[添加文件] [从文件夹批量添加]
────────────────────────────────────────────────────
已添加的文件                   │ 识别出的数据集
名称 / 位置 / 角色 / 归属       │ ○ 2500 K · run 02
run02.timeline.h5   事件证据    │   3 份证据文件
run02.species       物种丰度    │   物种：打开后自动准备
run02.reactionabcd  聚合反应    │   事件：来源已识别
其他目录下的 trajectory        │   轨迹：关联待验证
                              │
可以继续添加、移除或调整归属    │ ○ 2200 K · run 01
────────────────────────────────────────────────────
将分析：2500 K · run 02                  [取消] [开始分析]
```

这两项“添加”操作只影响同一个文件集合，没有两套识别规则、配置页或完成流程。
选取动作结束后，主界面展示研究数据及其关联，而不是继续要求用户在目录树中操作。

行为规则：

- 文件选择支持多选和跨位置追加；同一路径重复选择只保留一个引用。内容相同但路径
  不同的文件仅提示可能重复，不能凭文件大小或名字自动认定是同一运行。
- 自动识别文件角色，角色不明确时显示待识别；不要求普通用户逐项选择解析器。
- 有可靠运行来源的文件可自动归组；仅同名、同目录或同前缀只能生成建议。
- 待确认文件可指定归属、独立成组或移除。手动指定关联不等于证据验证通过，相关
  能力仍需经过格式、帧、原子和来源一致性检查。
- 同组同角色出现不兼容的多个来源时显示冲突并选择有效来源；不是“最后添加者覆盖”。
- 文件缺失、不可读或格式错误在对应行说明，只限制依赖它的能力；不清空整个添加集合。
- 只有坐标轨迹时提示补充 RNG 证据，不能把坐标解释成反应发生来源。
- 来源未识别的文件不能静默遗漏并呈现“全部导入成功”；界面明确已归组、待处理和
  不支持的项目。不支持的 `.route`、报告图像/HTML 不构成正式分析证据。
- 仅用户明确提交的组会成为 Current Dataset；关闭或取消面板保持原上下文。

### 3.6 视觉设计约束与交互验收

- 每个选择器只有一个高强调提交按钮，固定在底部；“添加文件”“移除”“取消”降低强调。
- 使用清晰标题、空白和少量分隔线建立层级，不为每条来源、能力或状态再包一层卡片。
- 文件清单是本次导入的主要内容，直接可见；源修订、schema、Workspace 等技术细节折叠。
- “已识别来源”“正在准备”“可查询”使用不同文案，不能一律显示绿色成功。
- 颜色表达选中、可用或异常，并配合文字；不把每一种索引分配一种强调色。
- 准备状态出现在分析任务旁，结果区域只呈现结果或明确的等待/空结果，不堆叠多个
  全局状态条、弹窗和告警来说明同一件事。

UI 验收除操作次数外，还要检查：用户无需展开维护面板就能确定将打开哪组数据；
多选和跨目录追加可用；每个文件的归属明确；未提交时顶部当前数据不变；
取消后能返回原位置；320–360 px 宽度下主操作和完整含义仍可见。

本提案配套交互草图使用示例数据，仅展示文件集合、自动归组、跨目录补充和准备后进入
分析的关系。它不是对现有 Dash 界面的截图，也不代表已经接通真实数据或完成产品验收。

## 4. 自动准备策略

采用 **按当前任务的依赖准备、按能力发布**，不把“自动准备”实现成默认 `prepare all`。

| 用户当前要做的事 | 系统安排的工作 | 不作为前置条件 |
| --- | --- | --- |
| 物种检索、丰度与元素分布 | 复用或准备 `.species` 对应索引及检索元数据 | 事件、轨迹索引 |
| 查看反应类型和聚合统计 | 使用合法聚合来源及其读取路径 | 轨迹、分子连续性 |
| 查看反应时间、具体发生或候选路线 | 准备该能力实际依赖的事件证据及派生结构 | 坐标轨迹 |
| 查看实例的几何和局部轨迹 | 复用事件证据，关联并准备轨迹索引 | 无关的批量分析 |
| 分子连续性或命运分析 | 满足该分析真实的分子证据和连续性依赖 | 无关功能的完成状态 |

第一阶段以已有构建器的真实发布粒度为准：当前若事件、连续性和候选结构由一个任务
整体准备，就等待它完整发布，不提前宣称其中一项已经可用。后续只有测量表明该耦合
显著拖慢首次分析时，才拆成可独立验证、带依赖版本的准备产物。

调度规则：

1. 已发布且兼容的产物直接复用；同源修订的活动任务直接附着，不重复创建。
2. 默认只启动当前任务需要的准备。用户进入新功能时，系统自动补齐依赖。
3. 单机默认限制同时进行的大型扫描；当前请求优先，避免多个能力争用磁盘和内存。
4. 后台任务保留阶段、检查点、取消和可恢复失败状态；重启后识别遗留任务并恢复状态。
5. 用户主动取消后不立即自动重启；再次发起相关分析才允许继续准备。
6. 重建前检查空间，包含 staging、已有发布版本和临时文件的共存占用；空间不足时
   就地提供更换 Workspace 或管理派生数据的动作，不自动清理已有结果。

仍提供高级“仅打开，不自动准备”及原有显式 prepare CLI。自动准备属于打开/执行分析
请求的协调流程，实际读取原始数据发生在后台 preparation；底层查询接口仍只读已发布索引。

## 5. 数据集不再等同于文件夹

以 **Dataset Identity + 明确的工件映射 + 源修订** 描述数据集。目录和公共前缀只是
首次发现的线索，不是后续所有行为必须反推的依据。

系统维护的描述记录包括：名称、Dataset Identity、各工件的角色和位置、选定的
Timed Evidence Source、来源验证结果、物理时间/长度/元素设置及其出处。
记录保存在 Dataset Workspace，用户无需手写清单；同一数据集的所有角色均可引用不同
目录的工件，不只为轨迹提供例外。已有数据集保留身份；多位置新数据集使用平台用户
Workspace，避免任意挑选某个来源目录作为“主目录”。常规单目录布局仍可沿用 sidecar。

为避免出现新的双重事实来源，扩展现有 manifest/settings 的职责并明确字段归属，
不另建一份与它们平行、可分别修改的配置。已发布索引绑定不可变的相关工件修订和
必要的解释参数版本；轨迹重新关联只使相关能力失效，不连带重建无关的物种索引。

匹配与检查分层进行：

- 首次发现只枚举受支持工件和有界元数据。同前缀仅产生候选，不足以证明来自同一运行。
- 打开时校验已有运行标识、格式、完整性声明及可有界检查的来源信息；有歧义时就地处理。
- preparation 流式检查相应帧、时间映射、参与原子和所需结构的一致性，在完整验证后发布。
  不能以少量抽样或“用户确认过路径”代替完整的证据验证。
- 无法证明的跨文件关系记录为限制；阻止依赖该关系的能力，保留独立来源可支持的分析。

保留原生 HDF5 优先规则；其存在但无效时，不静默切到 CSV。该错误只阻断依赖该来源的
能力；如果独立 `.species` 合法，仍允许进行相应分析。

快速检查使用文件属性和已有元数据，不在打开前对数百 GB 数据做全量散列。
必要的内容校验放入后台读取过程，并明确校验等级；大小与修改时间不是内容一致性证明。
正在变化的来源不能发布新索引，长期支持活跃模拟需要另行设计快照/封存协议。

## 6. 只在必要位置补充信息

| 情况 | 交互与分析限制 |
| --- | --- |
| 时间换算未知 | 允许按 Analyzed Frame / source timestep 查看；请求物理时间或速率时要求确认换算 |
| 长度单位未知 | 不阻断物种/反应检索；涉及物理距离、DFT 几何等能力时要求确认 |
| 元素映射未知 | 优先采用轨迹明确给出的元素；确实依赖 type 映射时才请求补充，不按 type 编号猜元素 |
| 多个可能轨迹 | 就地选择一次并保存关联，后台验证帧和原子对应关系 |
| 仅缺分子证据 | 限制要求分子实例和原子连续性的分析，不把未解析发生从统计中删除 |
| 原生来源损坏或尚未完成 | 说明受影响能力及更换/修复来源动作，不推荐无意义地反复建索引 |

用户确认的解释参数要绑定适用来源。换用新轨迹或新运行时，不能无条件沿用旧映射、
时间换算或长度单位。可靠的已记录元数据可以自动填充并显示出处，不重复询问已确认且
仍适用的信息。

## 7. 核心设计与会话正确性

新增一个负责“打开并满足分析依赖”的深模块；以下为概念 Interface，非已实现 API：

```python
preview(artifacts, associations=None) -> DatasetDrafts
open_dataset(selected_draft, intent, preparation_policy="required") -> OpenHandle
get_open_status(handle) -> OpenStatus
cancel_request(handle) -> OpenStatus
```

`artifacts` 是经过权限校验的显式文件引用集合；文件夹选取在进入此 Interface 前
完成枚举。`associations` 表示对建议归属的修正，不能跳过一致性验证。选中的草稿
必须绑定文件集合版本，迟到预览不能覆盖后续添加或移除。

`intent` 由当前页面提供，普通入口使用默认值，不新增强制“选择分析套餐”步骤。
Interface 返回稳定数据集引用、源修订、可用能力、任务句柄和必要用户输入。
调用方不再组合目录、`base`、source suffix、索引种类和任务触发次序。
取消请求与取消共享 Preparation Task 的关系由模块处理：移除一个等待者不能误杀其他
会话仍依赖的任务；需要停止任务时沿用明确的任务取消动作。

职责分配：

- `datasets.py` 统一输入解析和工件发现；CLI/Dash 共用，消除两套选择规则。
- 现有 `timed_evidence.py` 继续负责真实存在的 HDF5 / CSV Adapter 及来源规范化。
- 打开协调模块将用户意图转换为准备依赖，调用已有 `prepare.py` 和各 index/store。
- `dataset_context.py` 继续负责候选验证、Current Dataset 的事务化提交与过期请求隔离。
- `capabilities.py` 把来源、已发布产物及任务状态转成一致的用户能力说明。
- Dash 负责输入与显示；CLI/API 复用同一决策，显式 prepare 命令继续可用。

状态必须分成三个维度，不能引入“数据集 100% ready”：

1. 打开请求：检查中、需消歧、已提交、失败、已取消。
2. 各项 Analysis Capability：缺源、待准备、准备中、可用、过期、无效，以及必要的待补信息。
3. Preparation Task：排队、运行、取消、失败、完成，始终绑定特定数据集和源修订。

提交前失败保持原 Current Dataset；提交成功后，某项准备失败只影响对应能力，不再
把会话悄悄切回之前的数据。浏览、迟到验证、后台任务完成都不能擅自切换 Current Dataset。

待执行查询同时绑定 dataset_id、source revision、页面请求代次和参数摘要。换数据、
改查询或取消后，旧请求失效。来源变化不得自动重放旧查询；旧产物保留用于恢复，不能
因为仍在磁盘上就冒充当前修订，依赖已变化原始轨迹的历史导出也不能继续读取新文件。

## 8. 备选方案与取舍

| 方案 | 操作成本 | 主要代价 | 判断 |
| --- | --- | --- | --- |
| 保留分步检查向导，仅简化文案 | 仍需检查、确认、维护、返回分析 | 无法消除索引知识负担 | 收益不足 |
| 打开后立即准备全部能力 | 少手动操作 | 轨迹及重型连续性准备可能拖慢首个任务，浪费资源 | 作为可选高级动作 |
| 按当前任务自动准备，能力逐项开放 | 常规路径一次打开 | 需要可靠的依赖调度与请求恢复 | 推荐 |
| 先做上传平台、全局项目库、分布式任务 | 增加新的导入管理流程 | 引入传输、权限、部署和存储成本 | 不作为本次目标的前置条件 |

## 9. 分阶段交付

### 第一阶段：完成一次打开的核心体验

交付统一多文件选取、跨目录追加、角色识别、归组预览、冲突处理及明确工件描述；
文件夹选取复用同一链路。成功后进入原任务或默认物种入口。实现最小的按意图准备调度、复用/去重、能力自动刷新和待执行查询恢复。
沿用现有索引格式和真实发布粒度，保留手动管理入口。此阶段就应兑现“普通用户不用
手动建索引”，不能只改按钮和跳转。

### 第二阶段：完善补充来源和异常恢复

在第一阶段已支持跨目录文件集合的基础上，完善已有数据集补充来源及版本化设置依赖；将轨迹关联、单位和元素问题统一
为就地补充动作。完善空间不足、来源变化、重启恢复、移动目录和重复来源处理。
现有身份与 Workspace 可复用，不为引入新入口重置所有数据集 ID。

### 第三阶段：以测量决定性能结构调整

记录首次可分析时间、后台扫描量、峰值内存、索引空间和额外操作数。根据真实瓶颈，
决定是否把物种检索元数据持久化，或拆分当前较重的事件派生产物。
如果拆分，明确新的 schema、依赖版本、原子发布和旧索引兼容策略。
批量注册和上游 RNG 导出的可携带清单可以后续加入，不阻塞单数据集主流程。

## 11. 验收标准

- 单一、合法候选：添加所需文件后只需一次“开始分析”，没有强制独立检查页、
  数据概览或手动建索引步骤；最近数据集一次点击打开。
- 一次多选来自不同目录的事件、物种、聚合反应和轨迹文件，可以组织为同一数据集；
  不要求复制、重命名或整理目录。
- 同一批选择含两次运行时分别成组，未选组不切换 Current Dataset；同目录不强制合并。
- 文件夹批量选取与逐项多选产生相同的规范化文件集合、识别结果和能力判断。
- 后续补充文件只更新相应来源和依赖，不重置数据集身份；移除选项不删除源文件。
- 已有兼容索引：零次构建，进入目标任务；大型原始文件不被重新扫描。
- 缺索引：后台自动准备当前任务依赖；用户提交一次查询后，准备完成自动执行一次。
- 仅查看物种时不打开/扫描原始轨迹；后续进入轨迹时自动补齐真实依赖。
- 只有 `.species` 时可完成物种分析；事件/轨迹缺失不导致整个数据集打不开。
- 原生 timeline 无效且存在 CSV 时不静默回退；独立合法的丰度能力不被一并禁用。
- 取消、切换、改查询、重复点击、两个标签页同时请求时，无重复任务、错误结果提交或
  共享任务误取消；关闭页面不破坏已提交检查点。
- 中断恢复和发布失败不损坏已有产物；源修订变化阻止旧任务发布及旧查询自动执行。
- 首次进入耗时以“首次所需能力可用”为测量点，不用“页面已显示”冒充分析就绪。
  大型数据记录 wall time、peak RSS、索引大小及读取量；固定秒数承诺需实测后再制定。

本次为方案与界面草图更新，未修改 Dash 运行代码、执行索引构建或进行真实数据性能测试。
此前目录浏览草图的验收记录不代表本版文件集合设计已经通过产品集成验收。
本版示例草图在 Firefox 中通过了跨位置多选、待归属文件关联、明确选择当前数据集、
取消保留当前数据，以及文件夹批量选取进入同一文件集合的检查；736 和 320 px 宽度无
横向溢出。这里验证的是示例交互，实际来源验证、索引准备和 Dash 回调仍待实施。
